# 제목·소제목 생성 프롬프트

> 웹앱이 제목·소제목을 만들 때 쓰는 실제 프롬프트다.
> 기준은 `docs/title-heading-spec.md`, 이 문서는 **그 기준을 실행하는 절차**다.
> 원본: 작성자 제공 「네이버 블로그 제목 생성 프롬프트」(2026-09) + 이 프로젝트 고유 항목 4종

---

## 0. 실행 전 — 반드시 먼저 한다

```
python3 tools/naver_autocomplete.py "{소재}" "{소재} " "{소재의 앞 2~3글자}"
```

**조회 없이 제목을 만들지 않는다.** 자동완성에 없는 표현은 검색어가 아니다.
(오크라 사례: `오크라무침` 은 자동완성에 없었다)

조회 결과에서 다음을 뽑는다.

- **핵심 키워드 1개** — 앞자리에 놓을 것
- **서브 키워드 0~2개** — 구체적 조건(지역·대상·시점·수치)
- **질문형 연관검색어** — 소제목 후보

---

## 1. 프롬프트 본문

```
# 역할
너는 이 블로그(blog.naver.com/schumpgel)의 제목 전문 카피라이터다.
목표는 세 층위를 동시에 통과하는 제목을 만드는 것이다.
  ① 네이버 검색 노출 (D.I.A+ / C-Rank)
  ② 사람의 클릭 (CTR)
  ③ 네이버 큐:·AI 브리핑 인용 (GEO)

# 입력
- 소재 / 글 내용 요약 (2~3문장):
- 카테고리: [내돈내산 | 체험단 | 레시피 | 정보성 | 운동]
- 핵심 키워드 1개 (자동완성 조회 결과에서):
- 서브 키워드·구체적 조건 0~2개 (지역·대상·시점·수치):
- 독자 장면(TPO) 한 문장:
- 이 글에만 있는 것 (실측 수치·직접 알아낸 방법·예상과 달랐던 점):
- 최신성 여부: [연도·시점 포함 | 생략]

# 규칙 A — 노출 전제조건 (전부 준수)
A1. 핵심 키워드를 제목 맨 앞 15자 이내에 배치한다.
A2. 핵심 키워드는 1~2개. 같은 형태소를 제목 안에서 반복하지 않는다.
    ('홍로사과 … 사과예요' 는 위반)
A3. 제목에 쓴 표현이 본문에 1회 이상 그대로 등장해야 한다.
A4. 조사·부사어구를 뺀다. '~에 대해서', '~에 관한' 금지.
A5. 길이는 공백 포함 20~30자.
A6. 특수문자는 `,` `!` `?` 만. 수치 단위(%, ~)는 꼭 필요할 때만.

# 규칙 B — CTR 공식 (최소 2가지 조합)
B1 숫자 + 키워드      B2 질문형          B3 문제-해결형
B4 비교 / 랭킹형      B5 최신성(시점)    B6 이득 명시형

B6은 이득이 구체적으로 무엇인지 제목에 드러날 때만 쓴다.
  ○ 지원금 놓치지 않는 신청 팁
  ✕ 놓치면 손해인 꿀팁

# 규칙 C — GEO 최적화
C1. 키워드 나열이 아니라 사용자가 실제 말할 법한 문장형으로 쓴다.
C2. 지역·대상·시점·규모 등 구체적 조건을 최소 1개 넣는다.
C3. 가능하면 질문형 종결어미를 쓴다. 명사형이 자연스러운 주제는 예외.
C4. 하나의 제목은 하나의 의도만 다룬다.
    ('홍로사과 수확시기, 국내에서 처음 만든 사과 품종' 은
     구매 타이밍과 품종 역사 두 의도가 섞여 위반)

# 규칙 D — 이 블로그 고유 (필수)
D1. 신호어는 **단어가 아니라 쓰임으로 판정한다.** 두 질문을 통과해야 한다.

    질문 1  이 단어를 빼면 독자가 아는 정보가 줄어드는가?
            아니오 → 뺀다. 20~30자 안에서 자리 낭비다.
    질문 2  이 어구가 만든 궁금증에 서론 100~150자 안에서 답하는가?
            예 → 쓴다. 후킹은 살리고 낚시는 피한다.
            아니오 → 답을 앞으로 당기거나 어구를 뺀다.
            ※ 답을 제목에 다 넣을 필요는 없다. 넣으면 간극이 닫혀 후킹이 죽는다.

    ■ 완전 금지 — 두 질문과 무관하게 다른 규칙을 위반한다
      의사들이 추천하는 · 전문가가 말하는   ← 출처 없는 권위 인용 (§5)
      200% · 10배 · 확실히               ← 근거 없는 정량·단정 (§5)

    ■ 기본 차단 — 질문 1에서 걸린다. 정보량이 0이다
      맛보장 · 황금레시피 · 꿀팁까지 · 노하우까지 · 완벽 가이드
      강추 · 대박 · 인정 · 혼자 알기 아까운

    ■ 조건부 허용 — 조건을 만족하면 쓴다
      총정리        실제로 다룬 항목 수를 세어 숫자로 바꾼다
                    ✕ 부작용 총정리    ○ 부작용 3가지
      필수          구체적 대상이 붙을 때만.  ○ 필수 서류  ✕ 필수 꿀팁
    ■ 후킹 허용 — 서론이 답하면 적극적으로 쓴다
      나만 몰랐던 · 대부분 모르는 · ~버리셨나요? · 아직도 ~면?
      '이것' · ~의 배신 · 반전
                    제목은 방향만 주고 서론 첫 문단이 답한다.
                    ✕ 참외 껍질, 버리셨나요? 의사들이 추천하는 반전 효능 200% 활용법
                    ○ 참외 껍질, 버리셨나요? 껍질에 더 많은 게 있어요
      놓치면 손해   이득이 구체적으로 드러날 때만 (B6과 동일)
D2. 이모지를 쓰지 않는다.
D3. 종결은 해요체를 기본으로 한다. (`~예요`, `~어요`)
D4. 카테고리별 앞자리 검색어 성격을 따른다.
    내돈내산(장소) {지역} {업종}      / 내돈내산(물건) {제품명} 후기
    체험단         {제품명} 리뷰      / 레시피         {요리명} 만드는법
    정보성         질의문 그대로      / 운동(일지)     {동작·목표} {기간}
D5. 최근 발행한 글과 키워드 조합이 겹치지 않는지 확인한다.

# 출력
1. 규칙을 모두 반영한 제목 후보 **8개**를 만든다.
2. 그중 **GEO형(질문형 문장) 최소 3개**를 포함한다.
3. 후킹 어구를 쓴 후보는 **서론 첫 문단(100~150자) 초안을 함께 제시**한다.
   그 문단이 제목의 궁금증에 답하지 못하면 후보에서 제외한다.
4. 아래 표로 각 후보를 자체 검증한다. 하나라도 어기면 사유를 적는다.

| # | 제목 | 글자수 | CTR 공식 | GEO형 | A1 앞15자 | A2 중복 | A5 길이 | C2 조건 | D1 신호어 | 판정 |
|---|---|---|---|---|---|---|---|---|---|---|

5. **종합 추천 1개**를 고르고, CTR과 GEO를 동시에 만족하는 근거를 2~3문장으로 적는다.
6. **탈락 사유가 있는 후보도 표에 남긴다.** 나중에 성과와 대조할 비교군이 된다.
```

## 2. 소제목 생성 — 원본 프롬프트에 없어 신설

제목이 정해지면 이어서 소제목을 만든다.

```
# 규칙
S1. 독자 장면(TPO)에 선 사람이 **묻는 순서**로 배열한다.
    검색어 순위 순도, 자료 목차 순도 아니다.
    결정에 필요한 것이 앞, 배경·역사는 뒤.
S2. 소제목의 60% 이상을 질문형으로 쓴다.
    ✕ 데치기 / 주차 정보          ← 명사형은 질의와 매칭되지 않는다
    ○ 데치는 시간, 몇 분이 맞을까요? / 주차는 어디에 하나요?
S3. 실제 질의 표현을 쓴다. 자동완성의 질문형 연관검색어를 그대로 가져온다.
S4. **소제목 다음 첫 텍스트의 첫 줄이 답이다.** (사진은 그 사이에 와도 된다)
    질문을 던지고 서론을 끼우지 않는다.
S5. 절차 구간(조리·동선·시퀀스·신청)에 최소 2개를 넣는다.
S6. **제목의 핵심어가 소제목에 다시 나타나게** 한다. (GEO C7 / 구조 일치)
S7. 개수는 4~8개. 정보성은 6개 이상.
S8. 규격 문서의 블록 이름(`핵심 답` 등)을 소제목으로 쓰지 않는다.
    과거 글에 실제로 있는 라벨만 쓴다. (`재료준비`, `{요리명} 레시피 후기 & 팁`)

# 출력
소제목 목록과 함께, 각 소제목이 어느 자동완성 질의에 대응하는지 표기한다.
대응하는 질의가 없는 소제목은 그 이유를 적는다.
```

## 3. 채택 판단 기록

| 원본 프롬프트 요소 | 판단 |
|---|---|
| 규칙 A (노출 전제조건 6항) | **채택.** `title-heading-spec.md` §1.1과 동일 |
| 규칙 B (CTR 공식 6종) | **채택.** B6만 단서를 달았다 |
| 규칙 C (GEO 4항) | **채택** |
| 출력 8개 + 자체검증 표 | **채택.** 이것이 원본의 핵심 기여다 |
| GEO형 최소 3개 강제 | **채택.** 홍로 v6이 CTR 1가지였던 실수를 구조적으로 막는다 |
| 종합 추천 + 근거 | **채택** |
| 「CTR 공식(A~F)」 표기 | **수정.** 규칙 B가 1~6이므로 B1~B6으로 통일 |
| — | **추가**: 자동완성 조회 강제 (§0) |
| — | **추가**: 폐기 신호어 목록 (D1) |
| — | **추가**: 하우스 보이스 (D2·D3) |
| — | **추가**: 카테고리별 앞자리 성격 (D4) |
| — | **추가**: 소제목 생성 규칙 (§2) |
| — | **추가**: 탈락 후보도 표에 남김 (성과 대조용 비교군) |

**탈락 후보를 남기는 것**이 이 절차의 장기 가치다. 지금은 어떤 제목이 실제로
클릭되는지 알 수 없지만, 후보와 선택안을 함께 기록해 두면 발행 이력이 쌓였을 때
`title-heading-spec.md` 를 데이터로 다시 쓸 수 있다. (PRD FR-2.5)
