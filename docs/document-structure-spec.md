# 문서 구조 공통 규격

> 모든 카테고리가 이 문서를 상속한다. 각 프로파일의 문서 골격 절은 이 문서를 참조하고,
> 카테고리 고유 블록만 남긴다.
>
> **1차 근거**: `data/raw/naver_official/` — 네이버 검색 공식 콘텐츠 가이드
> **계기**: 레시피 초안 v7에서 재료준비 블록이 글의 열두 번째 덩어리에 있었다.
> 검색해서 들어온 독자가 재료를 보려면 서론 4문단과 Q&A 3개를 지나야 했다.
> 점검 결과 같은 문제가 네 카테고리에 전부 있었다.
> v8에서 한 번 더 걸렸다. 서론만 줄이고 잘라낸 내용을 바로 뒤에 옮겨
> 분량이 그대로였다. 그래서 법칙 4(소제목 판정)를 추가했다.

---

## 1. 공통 3법칙

### 법칙 1 — 서론은 3~5문장, 한 덩어리로

계기·배경·인사말을 늘리지 않는다. **한 덩어리 안에서 끝낸다.**
서론을 짧게 줄이고 잘라낸 내용을 바로 뒤 텍스트 블록으로 옮기는 것은
규칙만 지키고 문제를 남기는 것이다. 법칙 4로 판정한다.

```
1문장  독자의 상황을 짚는다        "오크라 사놓고 어떻게 먹을지 몰라 시들린 적 있으신가요."
2문장  결론을 먼저 준다            "2분 데쳐서 무치면 되는 15분 반찬이에요."
3문장  이 글의 관문을 예고한다      "어려운 건 물러지지 않게 데치는 것 하나뿐이에요."
4문장  [선택] 이번 건의 조건        "초록 오크라와 붉은 오크라를 섞어서 만들어 봤어요."
```

2문장의 **결론 선제시**가 핵심이다. 공식 가이드가 말하는 "핵심 정보를 쉽고 빠르게"에 대응한다.

### 법칙 2 — 핵심 정보 블록을 앞에

각 카테고리마다 **독자가 검색해서 들어온 이유**에 해당하는 블록이 있다.
그 블록은 **서론과 대표 이미지 바로 다음**에 온다. 배경 설명 뒤로 미루지 않는다.

| 카테고리 | 핵심 정보 블록 | 들어갈 것 |
|---|---|---|
| 레시피 | `재료준비` | 조리시간·인분·재료·계량 |
| 내돈내산(장소) | `정보블록` | 위치·영업시간·주차·가격대·대표메뉴 |
| 내돈내산(물건) | `제품 정보` | 제품명·가격·구입처·사용 기간 |
| 체험단 | `제품 정보` | 제품명·구성·규격·가격 (**대가성 고지가 그 위**) |
| 정보성 | `핵심 답 요약` | 제목이 던진 질문에 대한 3~5줄 결론 |
| 운동(일지) | `이번 회차 요약` | 기간·횟수·정량 변화 |
| 운동(수업) | `수업 정보` | 요일·시간·장소·정원·가격·문의처 |
| 운동(워크샵) | `워크샵 정보` | 일시·장소·비용·준비물 |

이 블록은 `quotation` 컴포넌트로 넣는다. 시각적으로 분리되고, 인용 단위로도 잘린다.

### 법칙 3 — 해석·배경·효능은 뒤로

재료의 유래, 성분표 비교, 브랜드 이야기, 개인적 감상은 **본문을 다 읽은 뒤**에 온다.
읽고 싶은 사람만 읽으면 되는 내용이다. 앞에 두면 정작 찾아온 정보를 가린다.

예외: **그 정보 없이는 다음 단계를 이해할 수 없을 때**만 앞에 둔다.
(예: 낯선 식재료의 정체를 2~3문장으로 짚는 것)

### 법칙 4 — 소제목 없이 설 수 있는 블록은 셋뿐

```
서론 · 클로징 · 번호 매긴 절차 단계
```

그 외 모든 본문 텍스트는 **소제목 아래**에 있어야 한다.

이 법칙은 법칙 1의 판정 도구이기도 하다.
**서론에 소제목을 붙이고 싶어진다면, 그건 서론이 아니라 본문 섹션이다.**
소제목이 필요하다는 감각은 "이 덩어리가 독립된 주제를 다루고 있다"는 신호다.
서론은 독립된 주제가 아니라 글로 들어가는 문이므로 소제목이 필요 없다.

읽기 편의만의 문제가 아니다. **소제목이 없으면 AI가 잘라 갈 손잡이가 없다.**
소제목 없는 본문 덩어리는 사실상 인용 대상에서 빠진다.

> **실제 사례** — 레시피 v8에서 서론을 3문장으로 줄인 뒤, 잘라낸 내용을
> 대표 이미지 뒤에 소제목 없는 텍스트 블록으로 붙였다. 규칙은 지켰지만
> 독자가 읽어야 할 분량은 그대로였고, 문제는 하나도 해결되지 않았다.
> 그 블록에 소제목을 붙일 수 있는지 물었더니 답이 나왔다.
> `오크라는 어떤 채소인가요?` 라는 소제목이 붙는 순간 그것은 섹션이 되었고,
> 조리에 필수가 아니므로 글 뒤로 갔다.

**서론에 남길지 뒤로 보낼지 가르는 질문**

```
이 내용 없이도 독자가 다음 단계를 할 수 있는가?
  예 → 뒤로 (소제목을 달아 섹션으로)
  아니오 → 서론에 한 문장으로
```

레시피 v9 적용 예:

| 내용 | 없어도 되나 | 결과 |
|---|---|---|
| 아욱과 아열대 채소, 7~9월 제철 | 예 | 뒤 FAQ `오크라는 어떤 채소인가요?` |
| 점액은 수용성 식이섬유 | 예 | 같은 FAQ로 |
| 초록·붉은 섞어서 만든다 | **아니오** — 이번 재료의 조건 | 서론에 한 문장 |

## 2. 표준 시퀀스

```
①  서명 라인          text          {한 줄 요약}_by{징키|링키}
②  훅 소제목          quotation     2줄
③  구분선
④  서론               text          3문장. 결론 선제시 포함
⑤  대표 이미지        image         첫 이미지 = 썸네일. 결과물 컷을 쓴다
⑥  [최소 배경]        text          2~3문장. 없으면 생략
⑦  핵심 정보 블록 ★  quotation     법칙 2 표 참조
⑧  본문 섹션          ── 반복 ─────────────────────
                      quotation     질문형 소제목
                      image         1~3장
                      text          3~7줄
                      ────────────────────────────
⑨  결과·완성 선언     text + image
⑩  후기 & 팁 ★       quotation     직접 겪은 것만
⑪  [심화 FAQ]         quotation     해석·배경·효능·성분. 출처 병기
⑫  클로징             text          3~4줄
```

★ 두 블록은 **모든 카테고리 필수**다. 누락 시 생성 차단.

⑤ 대표 이미지는 **결과물**을 쓴다. 완성된 요리, 방문한 공간의 전경, 제품 개봉 후 모습.
재료·부품·포장 상태를 첫 이미지로 쓰면 썸네일에서 무슨 글인지 알 수 없다.

## 3. 카테고리별 점검 결과와 수정

### 레시피 — 수정 완료

| 문제 | 수정 |
|---|---|
| 도입 4문단 | 4문장 한 덩어리로 |
| 서론에서 잘라낸 배경을 소제목 없이 뒤에 붙임 (v8) | 소제목 달아 글 뒤 FAQ로 (v9) |
| `재료준비`가 12번째 덩어리 | 3번째로 이동 |
| 정보 Q&A 3개가 재료 앞 | 성분 비교는 후기·팁 뒤로, 재료 소개만 2~3문장 남김 |
| 대표 이미지가 재료 컷 | 완성컷으로 교체 |
| 레드/그린 비교가 앞에 따로 | 데치기 단계 옆으로 이동 (중복 제거) |

### 내돈내산 — 수정 필요

| 문제 | 수정 |
|---|---|
| 도입 3~5줄 | 3문장 |
| 정보블록에 **가격대·대표메뉴가 없다** | 두 항목 추가. 검색 의도의 핵심이다 |
| 지도가 정보블록보다 앞 | 정보블록 → 지도 순서로. 텍스트가 먼저 인용된다 |
| 웨이팅·주차를 제목에 나열 | 제목에서 빼고 **질문형 소제목**으로 (`주차는 어디에 하나요?`) |

### 체험단 — 수정 필요

| 문제 | 수정 |
|---|---|
| **제품 정보 블록이 아예 없다** | 신설. 제품명·구성·규격·가격 |
| 대가성 고지가 배너 이미지에만 의존 | 텍스트 고지를 **서명 라인 바로 위**에 병기 |
| `추천 대상`·구매 링크가 맨 뒤 | 위치는 유지. 다만 본문이 정보 없이 홍보뿐이면 감점 대상 |

### 정보성 — 수정 필요 (가장 중요)

| 문제 | 수정 |
|---|---|
| **제목의 질문에 대한 답이 도입에 없다** | `핵심 답 요약` 블록 신설. 대표 이미지 직후 |
| 도입이 "문제 제기 + 답할 것 예고" | 예고가 아니라 **답을 준다**. 상세는 본문에서 |

정보성은 이 문제가 구조적이다. 답을 뒤로 미루는 구성이 곧 낚시 구조이고,
`docs/title-heading-spec.md` 에서 폐기한 후킹 어구 사전이 그 구성을 전제하고 있었다.
**제목이 질문이면 첫 화면에 답이 있어야 한다.** AI 브리핑 인용에도 이쪽이 압도적으로 유리하다.

```
제목   오크라 데치면 영양이 줄까요, 성분표로 비교했습니다
       ↓
핵심 답 요약 (대표 이미지 직후)
       비타민 C는 줄고, 식이섬유는 줄지 않습니다.
       100g 기준 비타민 C 11mg → 7mg,
       총 식이섬유 5g → 5.2g 입니다.
       (농촌진흥청 국가표준식품성분표 기준)
       ↓
본문   왜 그런지, 어떻게 확인했는지
```

### 운동 — 수정 필요

| 유형 | 문제 | 수정 |
|---|---|---|
| 수련 일지 | **10일치 나열만 있고 요약이 없다** | `이번 회차 요약` 블록 신설. 기간·횟수·정량 변화 |
| 수련 일지 | `기록 방식 안내`가 매 편 반복되는 상용구 | 클로징 직전으로 이동 또는 생략 |
| 수업 안내 | 가격·시간·장소가 본문에 흩어져 있다 | `수업 정보` 블록으로 묶어 앞에 |
| 워크샵 후기 | 일시·장소·비용이 없는 편이 있다 | `워크샵 정보` 블록 신설 |

수련 일지의 `이번 회차 요약`은 `docs/style-profile-training.md` §2.6의 정량 지표와 연결된다.
독자가 "31~40일 동안 뭐가 달라졌나"를 첫 화면에서 알 수 있어야 한다.

## 4. 발행 전 점검 (6항목)

```
[ ] 서론이 5문장 이내이고 한 덩어리다
[ ] 서론 안에 결론이 한 번 나온다
[ ] 대표 이미지가 결과물 컷이다
[ ] 핵심 정보 블록이 다섯 번째 덩어리 안에 있다
[ ] 해석·배경·효능이 본문 뒤에 있다
[ ] 같은 설명이 두 곳에 중복되지 않는다
[ ] 소제목 없는 텍스트 블록이 서론·클로징·절차 단계 외에 없다
```

네 번째 항목은 기계적으로 검사할 수 있다. **컴포넌트 인덱스로 세면 된다.**
