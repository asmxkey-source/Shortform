# 제목·소제목 공통 규격

> 모든 카테고리(내돈내산·체험단·레시피·정보성·운동)가 이 문서를 상속한다.
> 각 프로파일의 제목 절은 이 문서를 참조하고, 카테고리 고유 사항만 남긴다.
>
> **1차 근거**: `data/raw/naver_official/` — 네이버 검색 공식 게시글 4편
> (「AI 시대에 사용자의 선택을 받는 콘텐츠 작성 가이드」 본편·실전편, 「AI탭」 2편)
>
> **이 문서가 만들어진 이유**: 기존 제목 규격은 과거 글 표본에서 역산한 것이었다.
> 그 표본에는 클릭률도 인용 실적도 없다. 성과를 모르는 글에서 뽑은 패턴은
> 검증된 규칙이 아니라 **과거 습관의 재생산**이다. 근거를 공식 문서로 옮긴다.

---

## 0. 먼저 폐기하는 것

각 프로파일에 있던 **신호어 사전을 폐기한다.**

```
폐기: 황금레시피 · 맛보장 · 꿀팁까지 · 노하우까지 · 완벽 가이드
      추천! · 강추 · 총정리 · 대박 · 필수 · 인정
```

네이버 공식 가이드가 명시적으로 배제하는 항목에 해당한다.

> - "**반복적인 키워드 나열**, 낚시성 문서, 출처가 불분명한 짜깁기 글 … 은 걸러질 가능성이 높습니다"
> - "오직 노출만을 목적으로 **맥락과 관계 없는 키워드를 억지로 끼워 넣지 마세요**"
> - FAQ 6: "과거의 **기계적인 최적화 방식에서 벗어나** 사용자 중심으로 변화하고 있기 때문에
>   누구나 알 수 있는 뻔한 정보 대신 나만의 실제 경험과 지식이 훨씬 중요해졌습니다"

이 단어들은 **정보량이 0이다.** 제목 글자 수만 차지하고 독자에게 아무것도 알려주지 않는다.
`후기`, `레시피`, `만드는법`, `먹는법` 처럼 **글의 종류를 알려주는 단어는 신호어가 아니라
검색어의 일부**이므로 남긴다.

## 1. 제목 3원칙

```
[핵심 검색어 하나] , [이 글에만 있는 것]
```

### 원칙 1 — 핵심 검색어 하나를 앞에. 중복 금지

- 독자가 실제로 검색창에 칠 법한 표현 하나를 고른다
- **같은 단어를 두 번 쓰지 않는다.** `오크라무침 오크라손질법` 은 위반
- 키워드를 3개 이상 나열하지 않는다

### 원칙 2 — 뒤에는 이 글에만 있는 것

공식 가이드가 반복해서 요구하는 "창작자만이 알고 있는 팁"을 제목에 올린다.
다른 사람 글에도 있는 말이면 제목에 쓸 자격이 없다.

| 자리에 올 수 있는 것 | 예 |
|---|---|
| 직접 알아낸 방법 | `커피포트 물로 데치면 안 물러져요` |
| 실측 수치 | `데치는 시간 2분` |
| 예상과 달랐던 결과 | `데치면 비타민C가 줄어듭니다` |
| 판단 기준 | `붉은 오크라 색으로 확인하세요` |
| 대상·상황 한정 | `혼자 작업하기 좋은` / `주차 되는` |

### 원칙 3 — 제목이 약속한 것을 본문이 지킬 것

낚시 배제. 제목에 수치를 쓰면 본문에 그 수치가 있어야 하고,
제목에 "확인하는 법"을 쓰면 본문에 확인 절차가 있어야 한다.
**발행 전 자가 점검: 제목의 각 어절이 본문 어디에서 지켜지는지 짚을 수 있는가.**

### 길이

| 항목 | 규격 |
|---|---|
| 전체 | **25~40자** |
| 앞 15자 | 모바일 목록에서 잘리지 않는 구간. 핵심 검색어가 여기 있어야 한다 |
| 구분 | 쉼표 하나. `!`, `~`, 대괄호 남용 금지 |

## 2. 소제목 규격 — AI 인용의 실제 단위

**제목보다 소제목이 인용에 더 크게 작용한다.** AI 브리핑은 글 전체가 아니라
본문 조각을 인용하고, 그 조각을 자르는 손잡이가 소제목이다.

### 원칙 1 — 질문형으로 쓴다

독자가 검색창에 치는 문장 그대로가 가장 좋다.

```
○  오크라 데치는 시간, 몇 분이 맞을까요?
○  꼭지는 언제 자르나요?
○  주차는 어디에 하나요?
✕  데치기
✕  주차 정보
```

명사만 있는 소제목은 질의와 매칭되지 않는다.

### 원칙 2 — 소제목 바로 뒤에 답이 온다

질문을 던졌으면 다음 한두 문단 안에서 답한다. 서론을 끼우지 않는다.
AI가 그 한 덩어리만 떼어 가도 완결되어야 한다.

### 원칙 3 — 절차 구간에 최소 2개

조리 단계, 방문 동선, 운동 시퀀스, 신청 절차처럼 **순서가 있는 구간**은
공식 체크 가이드가 가장 강조하는 곳("절차 및 구체적 해결 과정")인데
번호만 있고 소제목이 없으면 잘라 갈 단위가 없다.

> 실전편 체크 가이드 2번: "실제 경험한 순서와 절차를 상세히 기술하였나요?
> 창작자만이 알고 있는 팁이나 주의 사항을 포함하였나요?"

### 개수

| 항목 | 규격 |
|---|---|
| 전체 | 4~8개 |
| 그중 질문형 | **최소 60%** |
| 절차 구간 | 최소 2개 |

## 3. 카테고리별 적용

원칙은 동일하다. **앞자리에 오는 검색어의 성격만 다르다.**

| 카테고리 | 앞자리 검색어 | 뒷자리에 올 것 | 예 |
|---|---|---|---|
| 내돈내산(장소) | `{지역} {업종}` | 그 장소에서 직접 확인한 조건 | `망원동 조용한 카페, 콘센트 자리 6개 세어봤어요` |
| 내돈내산(물건) | `{제품명} 후기` | 사용 기간·환경과 결과 | `보조배터리 3개월 후기, 기내반입 규정 확인했어요` |
| 체험단 | `{제품명} 리뷰` | 실사용 조건 (대가성 표시는 본문 첫 부분) | `LED 탁상시계 리뷰, 야간 밝기 3단계 재봤어요` |
| 레시피 | `{요리명} 만드는법` | 실패를 막는 조건·수치 | `오크라무침 만드는법, 커피포트 물로 데치면 안 물러져요` |
| 정보성 | 질의문 그대로 | 근거·출처 | `오크라 데치면 영양이 줄까요, 성분표로 비교했습니다` |
| 운동(일지) | `{동작·목표} {기간}` | 그 기간의 실측 변화 | `전굴 100일 기록, 손끝에서 바닥까지 4cm 줄었어요` |
| 운동(수업) | `{증상·고민} {수업명}` | 대상·조건 | `허리통증 코어밸런스 수업, 6명 정원으로 운영합니다` |

체험단은 제목에 대가성을 넣지 않는다.
표시 위치는 「추천·보증 등에 관한 표시·광고 심사지침」에 따라
**제목 또는 본문 첫 부분**이며, 이 프로젝트는 본문 첫 부분으로 통일한다
(`docs/style-profile-chehumdan.md` 참조).

## 4. 발행 전 점검 (7항목)

```
[ ] 같은 단어가 제목에 두 번 나오지 않는다
[ ] 폐기 신호어(맛보장·꿀팁까지·완벽 가이드·총정리 등)가 없다
[ ] 앞 15자 안에 핵심 검색어가 있다
[ ] 제목 뒷부분이 이 글에만 있는 내용이다
[ ] 제목의 모든 약속이 본문에서 지켜진다
[ ] 제목 앞자리 표현을 자동완성으로 조회해 확인했다
[ ] 소제목의 60% 이상이 질문형이다
[ ] 절차 구간에 소제목이 2개 이상 있다
```

## 5. 키워드는 작성 시점에 조회한다 — 추측 금지

제목·소제목·태그의 표현은 **365일 같지 않다.** 계절이 바뀌고 검색어가 바뀐다.
작성 시점에 실제 데이터를 조회해서 정한다. **머릿속에서 지어내지 않는다.**

### 3개 레이어

| 레이어 | 출처 | 로그인 | 알려주는 것 |
|---|---|---|---|
| **① 자동완성** | `ac.search.naver.com` | 불필요 | 지금 사람들이 쓰는 **실제 질의 표현** |
| **② 내 유입 검색어** | 크리에이터 어드바이저 | 필요 | 이 채널이 이미 먹히는 검색어 |
| **③ 주제 트렌드** | 크리에이터 어드바이저 트렌드 | 필요 | 주제 카테고리의 인기 유입 검색어·인기글 |

### 조회 시점 — 소재를 받은 직후, 되묻기 전

**제목을 정할 때가 아니라 글을 시작할 때 조회한다.**

```
✕  소재 접수 → 되묻기 → 본문 작성 → 제목 정할 때 조회
○  소재 접수 → 조회 → 되묻을 질문 결정 → 되묻기 → 본문 작성 → 제목
```

조회 결과가 **무엇을 되물을지**를 정하기 때문이다.

> **실제 사례** — 오크라 글에서 나는 본문을 다 쓴 뒤에 조회했다.
> 처음에 조회했다면 `오크라 데치기 시간` 이 질의라는 것을 알았을 것이고,
> 그러면 첫 질문이 "실패한 경험이 있나요?" 가 아니라
> **"몇 분 데치셨어요?"** 였을 것이다.
> 그 수치는 한참 뒤에야 받았고, 결국 제목이 되었다.
> **조회를 늦게 하면 되묻기가 헛돈다.**

조회 결과는 세 가지를 정한다.

| 정하는 것 | 방법 |
|---|---|
| 되물을 질문 | 상위 질의가 요구하는 정보부터 묻는다 |
| 소제목 세트 | 상위 질의를 그대로 소제목으로 |
| 제목 앞자리 | 1순위 질의 표현 |

### ① 자동완성 — 지금 바로 쓸 수 있다

`tools/naver_autocomplete.py` 로 조회한다. 로그인이 필요 없고 실시간이다.

```
python3 tools/naver_autocomplete.py 오크라 "오크라 데" "오크라 손질"
```

**제목 앞자리는 반드시 이 조회를 거친다.** 자동완성에 뜨지 않는 표현은 검색어가 아니다.

> **실제 사례 (2026-09-01)** — 오크라 글의 제목 앞자리에 `오크라무침` 을 놓았는데,
> 조회해 보니 `오크라 무침` 도 `오크라무침` 도 자동완성에 **없었다.**
> 반면 `오크라 데치는법`, `오크라 데치기 시간` 은 실제 질의로 존재했고
> 그것이 이 글의 핵심 내용이었다. 앞자리를 교체했다.
>
> **원칙 1을 지킨 줄 알았지만 검색어가 아닌 것을 검색어 자리에 넣고 있었다.**
> 조회 없이는 이 실수를 알 수 없다.

### ②③ 크리에이터 어드바이저 — 로그인 세션이 필요하다

`https://creator-advisor.naver.com/naver_blog/{blogId}/trends`

도메인은 접근 가능하나 로그인 리다이렉트(302)가 걸린다.
**M2에서 발행용 Playwright 세션을 확보하므로, 같은 세션으로 조회한다.**
별도의 인증 체계가 필요 없다.

| 항목 | 용도 |
|---|---|
| 인기 유입 검색어 | 이 블로그가 이미 상위에 있는 검색어. C-Rank가 붙은 주제다 |
| 주제별 트렌드 차트 | 같은 주제 카테고리에서 지금 뜨는 검색어 |
| 인기글 | 경쟁 문서의 제목 형태 |
| 이용자 분석 | 성별·연령. 어휘 선택에 반영 |

### 가드레일 — 소재는 경험이, 각도는 데이터가

네이버 공식 가이드 원칙 2는 **일관된 주제**를 요구한다.

> "AI 검색 엔진은 특정 주제에 대해 지속적으로 양질의 글을 발행하는 채널을
> 해당 분야의 '전문 출처'로 인식합니다."

트렌드를 좇아 소재를 고르면 이 원칙과 정면으로 충돌한다.
또한 맥락 없는 트렌드 키워드를 본문에 끼워 넣는 것은
공식 가이드가 배제하는 **"무관한 키워드 삽입"** 에 해당한다.

```
데이터가 정하는 것   각도(어떤 질문에 답하는 글인가) · 되물을 질문
                     제목 앞자리 · 소제목 문장 · 태그
경험이 정하는 것     소재(무엇에 대해 쓰는가) · 본문 내용
```

**소재는 겪은 것 중에서만 고른다.** 겪지 않은 것을 트렌드라고 쓰면
공식 가이드 원칙 1(직접 경험한 지식)에 걸리고, 이 제품의 정체성에도 어긋난다.

**그러나 각도는 데이터가 정한다.** 같은 경험도 어떤 질문에 답하는 글로 쓰느냐에 따라
검색 유입이 완전히 달라진다.

> **실제 사례** — 오크라무침을 만든 경험 하나로 쓸 수 있는 글은 여러 개다.
>
> | 각도 | 자동완성 존재 |
> |---|---|
> | 오크라무침 레시피 | **없음** |
> | 오크라 데치는법 | 있음 |
> | 오크라 먹는법 | 있음 |
> | 오크라 효능 | 있음 |
>
> 같은 재료로 만든 같은 음식인데, 첫 번째 각도로 쓰면 아무도 안 들어온다.
> **소재를 바꾼 것이 아니라 각도를 바꾼 것이다.**

본문에 키워드를 억지로 끼워 넣는 것은 여전히 금지다.
각도를 정한다는 것은 **그 질문에 실제로 답하는 글을 쓴다**는 뜻이지,
같은 글에 키워드만 뿌린다는 뜻이 아니다.

조회한 키워드라도 **본문이 실제로 그 질문에 답하지 않으면 배제**한다.
`오크라 효능` 이 상위 질의여도, 본문에 효능 내용이 없으면 태그에 넣지 않는다.
제목 3원칙의 세 번째(약속 이행)가 여기에도 적용된다.

## 6. 아직 검증되지 않은 것 — 측정 루프가 필요하다

이 문서의 원칙은 **네이버 공식 문서에서 도출한 것이지, 성과로 검증된 것이 아니다.**
네이버는 CTR을 공개하지 않는다. 검증 경로는 하나뿐이다.

### 웹앱에 넣을 것 (PRD 반영 대상)

1. **제목 후보 기록** — 발행 시 생성한 후보 3개와 실제 선택안을 함께 저장
2. **2주 후 대조** — 블로그 통계의 유입 검색어·조회수를 제목과 대조
3. ~~자동완성 조회~~ → **§5로 정식 편입.** `tools/naver_autocomplete.py` 로 구현됨
4. **인용 여부 기록** — AI 브리핑 인용이 확인되면 그 글의 제목·소제목 형태를 태깅
5. **원칙 갱신** — 위 데이터가 30편쯤 쌓이면 이 문서를 데이터 기반으로 다시 쓴다

**그때까지 이 문서는 "공식 문서에 근거한 최선의 가설"이지 확정된 법칙이 아니다.**
과거 글에서 역산한 규칙보다는 낫지만, 측정 없이는 그다음으로 갈 수 없다.
