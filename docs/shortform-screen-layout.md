# 숏폼 화면 구성 분석 및 자동 생성 규격

> 목적: 인기 숏폼에서 반복적으로 관측되는 **화면 문법(프레이밍 · 자막 위치 · 컷 전환 · 정보 배치)** 을
> 영상 생성 파이프라인이 그대로 소비할 수 있는 **수치 규격과 중간 스키마**로 변환한다.
> 개별 히트작 순위를 다루지 않고, "재현 가능한 레이아웃 규칙"만 다룬다.

---

## 1. 핵심 결론 (자동화 기본값)

단일 플랫폼 최적화보다 **TikTok · Instagram Reels · YouTube Shorts 공통 세로형 몰입 구조**를 베이스로 잡는다.
조회수는 TikTok이 우세하고 참여율은 Shorts가 강한 등 플랫폼별 강점이 갈리므로, 공통 문법을 템플릿화하고
플랫폼별 차이는 출력 단계 옵션으로 분기하는 편이 재사용성이 높다.

| 항목 | 기본값 | 비고 |
|---|---|---|
| 캔버스 | 1080 × 1920 (9:16) | 고정 |
| 총 길이 | 15 ~ 25초 (기본 22초) | 짧은 버전 우선 |
| 프레임레이트 | 30fps (렌더 기준) | 소스가 60fps면 다운샘플 |
| 훅 제시 | 0.0 ~ 2.0초 | 결과/약속을 먼저 |
| 첫 3초 시각 변화 | 2회 이상 | 컷·줌·텍스트카드 중 무엇이든 |
| 컷 간격 | 오프닝 ≤1.0초 / 본문 2 ~ 3초 | 3단 템포 |
| 패턴 인터럽트 | 전체 길이의 40 ~ 60% 지점 1회 | 줌·소품·앵글 변경 |
| CTA | 마지막 2 ~ 3초 | 긴 로고 아웃트로 금지 |
| 레이아웃 베이스 | 상단 훅 + 중앙 피사체 + 하단 자막 | 3층 오버레이 |

## 2. 인기 숏폼의 공통 특성

장르가 달라도 다음 3가지가 공통으로 관측된다.

1. **보상 선지급** — 첫 1~2초 안에 "이 영상을 보면 무엇을 얻는지"를 약속하거나 결과 장면을 먼저 보여준다.
   스크롤 이탈 여부가 결정되는 구간이 매우 짧기 때문에, 오프닝은 설명이 아니라 결과로 시작한다.
2. **초반 고밀도 시각 변화** — 첫 3초 동안 최소 1초당 1회 이상 화면이 변한다.
3. **언어 의존도 최소화** — 시각 중심 콘텐츠가 강세다. 텍스트 없이도 무슨 일이 일어나는지 읽히는 구성이 유리하다.

자동화 관점 함의: **"오프닝 생성"과 "본문 생성"을 다른 규칙 집합으로 분리해야 한다.**
전 구간을 같은 템포·같은 정보 밀도로 만들면 인기 숏폼 문법에서 벗어난다.

## 3. 캔버스와 좌표 규격

### 3.1 안전 영역 (하드 제약)

플랫폼 UI(사이드 액션 버튼, 계정명, 캡션, 진행 바)가 화면 가장자리를 가린다.
따라서 **중요 텍스트와 얼굴은 중앙 1080 × 1420 안전 영역 안**에 둔다.

```
y=0     ┌────────────────────────────┐
        │  상단 UI 예약 (250px)       │  ← 텍스트/얼굴 금지
y=250   ├────────────────────────────┤
        │                            │
        │   SAFE AREA 1080 × 1420    │
        │                            │
y=1670  ├────────────────────────────┤
        │  하단 UI 예약 (250px)       │  ← 자막 바닥 붙임 금지
y=1920  └────────────────────────────┘
```

| 항목 | 값 |
|---|---|
| 캔버스 | `w=1080, h=1920` |
| 상단 예약 | `y 0 → 250` |
| 하단 예약 | `y 1670 → 1920` |
| 세로 안전 영역 | `y 250 → 1670` (1420px) |
| 좌우 여백(권장) | `x 60 → 1020` (텍스트 기준) |

> Reels 기준으로 명시된 규격이지만, TikTok · Shorts도 동일한 모바일 세로 소비 패턴이므로 공통 적용한다.

### 3.2 오버레이 밴드 (텍스트 배치 좌표)

영역은 **서로 겹치지 않는 텍스트 밴드**로 정의하고, 그 아래 영상 레이어는 전체 캔버스를 채운다.

| 밴드 키 | 역할 | y 범위 | 높이 | 정렬 |
|---|---|---|---|---|
| `top_safe` | 훅 텍스트 | 260 → 560 | 300 | 가운데 정렬, 상단 기준 |
| `main_action` | 핵심 피사체(영상) | 460 → 1612 | 1152 (60%) | 시각 중심 |
| `lower_safe` | 본문 요약 자막 | 1240 → 1560 | 320 | 가운데 정렬, 하단 기준 |
| `cta_center` | CTA | 760 → 1160 | 400 | 화면 정중앙 |

* `main_action`은 텍스트 밴드가 아니라 **피사체 무게중심 기준 존**이다. 오버레이와 z축으로 겹친다.
* 피사체 무게중심 목표: `y ≈ 860 ~ 960` (프레임 중앙).
* 토킹헤드는 예외: **눈높이를 프레임 상단 35% 지점(y ≈ 672)** 에 둔다.

### 3.3 레이어 z-order

```
z4  CTA / 엔드카드
z3  훅 텍스트 (top_safe)
z2  본문 자막 (lower_safe)
z1  그래픽 요소 (지시선, 번호 배지, 프로그레스)
z0  영상 / 아바타 / 화면 캡처 (full-bleed 1080×1920)
```

렌더러는 z0만 소스 미디어에 의존하고, z1~z4는 스키마에서 결정적으로 생성된다.
→ **텍스트 생성기와 비디오 렌더러를 완전히 분리할 수 있는 지점.**

## 4. 4단 화면 구성 패턴

가장 자주 관측되는 구조.

| # | 영역 | 화면 비중 | 담는 것 | 밴드 키 |
|---|---|---|---|---|
| 1 | 훅 | 상단 15 ~ 20% | 문제 제기, 결과 약속, 전후 대비 문구 | `top_safe` |
| 2 | 메인 액션 | 중앙 55 ~ 65% | 얼굴, 손동작, 제품, 음식, 게임 장면 | `main_action` |
| 3 | 정보 보조 | 중하단 15 ~ 20% | 핵심 포인트, 번호형 단계, 짧은 설명 | `lower_safe` |
| 4 | CTA | 마지막 2 ~ 3초 | 저장 · 댓글 · 프로필 · 다음 편 유도 | `cta_center` |

### 핵심 원칙: 한 샷에 한 메시지

화면 안에 요소를 많이 넣지 말고, **컷을 나눠 메시지를 순차 전달**한다.
완료율과 이해도를 동시에 유지하는 유일한 방법이다.

파이프라인 규칙으로 환산하면:

* 한 샷에 표시 가능한 텍스트 카드 = **1개** (훅 구간에서만 훅+키워드 2개 허용)
* 한 샷의 `purpose` 값 = **1개**
* 포인트가 3개면 샷도 최소 3개

## 5. 자막 · 텍스트 규격

### 5.1 공통 규칙

| 항목 | 규격 |
|---|---|
| 카드당 줄 수 | 2줄 이내 |
| 노출 시간 | 카드당 2.0 ~ 2.5초 |
| 샷당 단어 수 | 8 ~ 12 단어 |
| 대비 | 고대비 필수 (외곽선 또는 스크림 배경) |
| 바닥 붙임 | 금지 (`lower_safe` 하한 y=1560 준수) |
| 워터마크 | 플랫폼 워터마크 제거 |

### 5.2 줄당 글자 수 — 언어별 보정

원 규격의 "한 줄당 42~55자"는 **라틴 문자 기준**이다. 한글은 글자 폭이 약 2배이므로 그대로 쓰면
`top_safe` 밴드를 넘긴다. 아래 값을 언어별 기본값으로 둔다.

| 언어 | 줄당 권장 | 근거 |
|---|---|---|
| 영문 | 42 ~ 55자 | 원 규격 |
| 한글 | 18 ~ 24자 | 원 규격을 전각 폭으로 환산한 파생값 |

> ⚠️ 한글 값은 원문에 없는 **파생 추정치**다. 실측 렌더 후 조정 대상.

### 5.3 텍스트 3분류 (섞지 않는다)

| 종류 | 밴드 | 톤 | 예 |
|---|---|---|---|
| `hook_text` | `top_safe` | 약속 / 도발 / 대비 | "3초 안에 핵심만" |
| `body_text` | `lower_safe` | 요약 / 번호 단계 | "① 안전영역 먼저 잡기" |
| `cta_text` | `cta_center` | 행동 유도 | "저장하고 다음 편 보기" |

세 범주를 한 밴드에 섞으면 화면 혼잡도가 급격히 올라간다. **스키마에서 밴드-범주 매핑을 강제한다.**

### 5.4 스타일 기본값 (1080×1920 기준)

| 종류 | 크기 | 굵기 | 색 | 처리 |
|---|---|---|---|---|
| 훅 | 76 ~ 88px | Black / 900 | #FFFFFF | 외곽선 6px #000 또는 상단 그라데이션 스크림 |
| 본문 자막 | 52 ~ 64px | Bold / 700 | #FFFFFF | 하단 그라데이션 스크림 |
| 번호 배지 | 48px | Black | 강조색 | 원형 배경 |
| CTA | 64 ~ 72px | Black | #FFFFFF | 반투명 박스 |

## 6. 컷 편집 리듬 — 3단 템포

전 구간을 같은 템포로 만들면 안 된다.

```
0s ──────── 3s ──────────────── 40~60% ──────────── 마지막 3s ── 끝
  [고속]        [중속 2~3초 비트]   ★패턴 인터럽트     [재압축]
  점프컷          안정된 정보 전달    줌/소품/앵글변경     CTA·루프
  볼드 텍스트카드
  클로즈업 전환
```

| 구간 | 템포 | 필수 요소 |
|---|---|---|
| 오프닝 (0 ~ 3초) | 고속, 컷 ≤ 1.0초 | 시각 변화 2회 이상, 훅 텍스트 |
| 본문 (3초 ~ 80%) | 중속, 컷 2 ~ 3초 | 포인트당 1샷 |
| 인터럽트 (40 ~ 60% 지점) | 순간 변화 1회 | 줌 · 소품 등장 · 앵글 변경 |
| 엔딩 (마지막 2 ~ 3초) | 재압축 | CTA 또는 루프 연결 |

## 7. 반복적으로 강한 포맷

자동화 1차 구현 대상은 다음 두 축으로 나누는 것이 합리적이다.

| 축 | 성격 | 적합 주제 | 대응 템플릿 |
|---|---|---|---|
| 설명형 튜토리얼 | 정보 전달, 단계 제시 | AI · 마케팅 · 노하우 | 템플릿 A |
| 시각 중심 | 언어 의존 최소, 감각 자극 | 제품 데모 · 결과 강조 | 템플릿 B |

토킹헤드는 위 두 축의 변형으로 취급한다 (템플릿 C).

## 8. 레이아웃 템플릿

### 템플릿 A — 설명형 숏폼 (기본 22초)

| 구간 | 화면 | 텍스트 |
|---|---|---|
| 0 ~ 2초 | 중앙: 결과 화면 또는 문제 장면 | 상단 훅 + 하단 키워드 자막 |
| 2 ~ 10초 | 핵심 포인트 2 ~ 3개, **샷별 1개씩** | 하단 번호형 자막 |
| 10 ~ 18초 | 전후 비교 · 예시 · 데모 화면 | 하단 짧은 설명 |
| 18 ~ 22초 | 정리 화면 | CTA (저장 / 팔로우 / 다음 편) |

### 템플릿 B — 시각 몰입형 숏폼 (기본 18초)

| 구간 | 화면 | 텍스트 |
|---|---|---|
| 0 ~ 1.5초 | **결과 장면부터 시작** | 3 ~ 6단어로 최소화 |
| 1.5 ~ 8초 | 액션 중심 컷을 1초 내외로 연속 배치 | 거의 없음 |
| 8 ~ 15초 | 만족감 최고점 클로즈업 또는 반전 컷 | 짧은 강조어 |
| 15 ~ 18초 | 루프 연결 프레임 | 짧은 반응 유도 문구 |

* 루프형 엔딩: 마지막 프레임과 첫 프레임의 구도·색조를 맞춰 재생 이음새를 감춘다.

### 템플릿 C — 인터뷰 / 토킹헤드형 숏폼

| 항목 | 규격 |
|---|---|
| 얼굴 위치 | 중앙보다 약간 상단 |
| 눈높이 | 프레임 상단 35% (`y ≈ 672`) |
| 자막 | `lower_safe` 안쪽, 바닥 붙임 금지 |
| B-roll 삽입 | 2 ~ 3초마다 (손동작 · 화면 캡처 · 자료 컷) |
| 목적 | 정면 독백 피로 감소 |

## 9. 중간 스키마

프롬프트보다 **중간 스키마**가 자동화의 핵심이다.
`shot` 단위 구조를 두면 텍스트 생성기(LLM)와 비디오 렌더러를 분리할 수 있다.

### 9.1 최소 형태 (원안)

```json
{
  "platform": "reels|shorts|tiktok",
  "aspect_ratio": "9:16",
  "duration_sec": 22,
  "hook": {
    "text": "3초 안에 핵심 약속",
    "position": "top_safe",
    "start": 0.0,
    "end": 2.0
  },
  "shots": [
    {
      "start": 0.0,
      "end": 2.0,
      "visual_type": "result|face|product|screen|broll",
      "subject_position": "center",
      "caption": "짧은 키워드 자막",
      "caption_position": "lower_safe",
      "motion": "jump_cut|zoom|pan|static",
      "purpose": "hook"
    }
  ],
  "cta": {
    "text": "저장하고 다음 편 보기",
    "start": 18.0,
    "end": 22.0
  }
}
```

### 9.2 핵심 4필드

이 네 가지가 정리되면 LLM은 대본과 자막을, 렌더러는 배경 영상 · 아바타 · 화면 캡처 · 전환 효과를
**규칙 기반으로** 조립할 수 있다.

| 필드 | 결정하는 것 | 허용값 |
|---|---|---|
| `visual_type` | z0 레이어에 무엇을 채울지 | `result` `face` `product` `screen` `broll` |
| `subject_position` | 피사체 무게중심 좌표 | `center` `upper_center` `left` `right` |
| `caption_position` | 텍스트 밴드 선택 | `top_safe` `lower_safe` `cta_center` |
| `purpose` | 편집 템포와 검증 규칙 분기 | `hook` `point` `demo` `interrupt` `payoff` `cta` |

`purpose`가 편집 리듬을 결정한다 — `hook`은 ≤1.0초, `point`는 2~3초, `interrupt`는 40~60% 구간에만 허용.

### 9.3 확장 필드

실제 렌더까지 자동화하려면 다음이 추가로 필요하다.
전체 정의는 [`schemas/shortform-video.schema.json`](../schemas/shortform-video.schema.json) 참조.

| 필드 | 용도 |
|---|---|
| `canvas` | width / height / fps / safe_area — 렌더 하드 제약 |
| `template` | `A` `B` `C` — 검증 규칙 프로파일 선택 |
| `shots[].framing` | `wide` `medium` `closeup` `extreme_closeup` |
| `shots[].visual_source` | 소스 조달 방법 (`stock` `generate` `asset` `screen_capture` `avatar`) |
| `shots[].transition_in` | `cut` `jump_cut` `whip` `dissolve` |
| `shots[].pattern_interrupt` | 인터럽트 샷 표시 (템플릿별 1회) |
| `styles` | 훅 / 자막 / CTA 폰트·색·스크림 |
| `audio` | 음악 스타일 · BPM · 보이스오버 |
| `loop_ending` | 루프 연결 여부 (템플릿 B) |

## 10. 파이프라인 구조

```
[주제 입력]
     │
     ▼
① 기획 LLM ──→ 템플릿 선택 (A/B/C) + 포인트 목록 추출
     │
     ▼
② 대본 LLM ──→ shot 배열 생성 (텍스트 3분류 준수)
     │
     ▼
③ 스키마 검증기 ──→ §11 규칙 위반 시 ②로 반송 (최대 N회)
     │
     ▼
④ 소스 조달기 ──→ visual_source 별로 스톡/생성/캡처/아바타 수집
     │
     ▼
⑤ 렌더러 ──→ z0 미디어 + z1~z4 오버레이 결정적 합성
     │
     ▼
⑥ 출력 검증 ──→ 안전영역 픽셀 검사, 길이, 워터마크
```

핵심: **③ 스키마 검증기가 LLM 출력과 렌더러 사이의 계약**이다.
검증기를 통과한 스키마는 항상 렌더 가능해야 한다. 렌더러 안에 판단 로직을 두지 않는다.

## 11. 검증 규칙 체크리스트

파이프라인에 린터로 구현할 항목. `severity`는 `error`(반송) / `warn`(경고 후 통과).

| ID | 규칙 | 검사식 | severity |
|---|---|---|---|
| `C01` | 캔버스 1080×1920 / 9:16 고정 | `canvas.width==1080 && canvas.height==1920` | error |
| `C02` | 핵심 객체 안전 영역 유지 | 모든 텍스트 bbox ⊂ `y[250,1670] × x[60,1020]` | error |
| `C03` | 첫 2초 안에 훅 제시 | `hook.end <= 2.0` 또는 첫 샷 `purpose=="hook"` | error |
| `C04` | 첫 3초 시각 변화 2회 이상 | `count(shot boundaries in [0,3]) >= 2` | error |
| `C05` | 자막 2줄 이내 | `lines(caption) <= 2` | error |
| `C06` | 자막 바닥 침범 금지 | 자막 bbox 하한 `<= 1560` | error |
| `C07` | CTA는 마지막 2~3초 | `duration - cta.start` ∈ `[2,3]` | error |
| `C08` | 긴 로고 아웃트로 금지 | 로고 전용 샷 길이 `<= 1.0` | warn |
| `C09` | 워터마크 제거 | 소스 메타에 platform watermark 플래그 없음 | error |
| `C10` | 한 샷 한 메시지 | 샷당 텍스트 카드 `<= 1` (훅 구간 예외 2) | error |
| `C11` | 자막 노출 시간 | 카드 노출 `2.0 <= t <= 2.5` | warn |
| `C12` | 샷당 단어 수 | `8 <= words <= 12` (템플릿 B는 `3~6`) | warn |
| `C13` | 본문 컷 간격 | 3초 이후 샷 길이 `2.0 ~ 3.0` | warn |
| `C14` | 패턴 인터럽트 1회 | `pattern_interrupt==true` 샷이 `duration*0.4~0.6` 안에 정확히 1개 | warn |
| `C15` | 총 길이 | `15 <= duration_sec <= 25` | warn |
| `C16` | 텍스트-밴드 매핑 | `hook→top_safe`, `body→lower_safe`, `cta→cta_center` | error |
| `C17` | 타임라인 연속성 | 샷 구간이 겹치지 않고 `[0, duration]`을 빈틈없이 덮음 | error |
| `C18` | 토킹헤드 눈높이 | 템플릿 C에서 `face` 샷 눈높이 `y ≈ 672 ± 60` | warn |

### 템플릿별 규칙 오버라이드

일부 규칙은 템플릿마다 값이 다르다. 린터는 `template` 값으로 프로파일을 선택한다.

| 규칙 | 템플릿 A | 템플릿 B | 템플릿 C |
|---|---|---|---|
| `C12` 샷당 단어 수 | 8 ~ 12 | 3 ~ 6 | 8 ~ 12 |
| `C13` 본문 컷 간격 | 2.0 ~ 3.0초 | 0.8 ~ 1.5초 (1.5 ~ 8초 구간) | 2.0 ~ 3.0초 |
| 기본 길이 | 22초 | 18초 | 20초 |
| `subject_position` 기본값 | `center` | `center` | `upper_center` |
| 자막 밀도 | 샷마다 | 강조 샷에만 | 샷마다 |
| 추가 규칙 | — | `loop_ending=true` 권장 | B-roll 2 ~ 3초마다 삽입 |

## 12. 근거와 확신도

| 구분 | 항목 |
|---|---|
| **원문 근거 (직접 인용)** | 1080×1920 · 안전영역 1080×1420 · 상하 250px · 4단 구조 비중 · 2줄/42~55자 · 8~12단어/2.0~2.5초 · 첫 3초 시각변화 · 40~60% 인터럽트 · 눈높이 상단 35% · 템플릿 A/B/C 타임라인 · 스키마 원안 · 체크리스트 7항목 |
| **파생 추정 (본 문서에서 계산)** | 오버레이 밴드 y 좌표 · 한글 줄당 18~24자 · 폰트 크기 기본값 · z-order · 검증 규칙 ID와 검사식 · 파이프라인 6단계 |
| **미검증 / 실측 필요** | 한글 자막 실렌더 폭 · 플랫폼별 UI 침범 영역 실측 · 30fps 결정 · `visual_source` 조달 성공률 |

> 원문의 통계 주장(TikTok 평균 조회수 우위, Shorts 참여율 강세, Shorts 소비의 상당 비중이 25초 이하,
> 엔터테인먼트 계열 비중)은 출처 식별자만 있고 실제 출처 목록이 없어 **본 문서에서 재검증하지 않았다.**
> 레이아웃 수치 규격은 검증 여부와 무관하게 그대로 쓸 수 있으나, 플랫폼 선택 근거로 인용할 때는 원출처 확인이 필요하다.
