## A. 내가 사실이 아닌 것을 확정형으로 쓴 것 — 2건

가장 심각한 분류다. 둘 다 작성자가 확인해 준 적 없는데 단정형으로 썼다.

| # | 초안 | 발행본 |
|---|---|---|
| 1 | `2분입니다.` | **`1분 30초~2분입니다.`** |
| 2 | `큰 오크라는 심이 억셀 수 있어요` / `어슷 썰어 모양을 내는 것보다 잘게 써는 편이 부드러워요` | **`굵은 오크라는 세로로 반 가른 다음 썰어주시면 식감이 좋아요`** |

1번은 작성자가 "대체로 2분 안에"라고 말한 것을 `2분입니다` 로 좁혔다.
**범위를 점으로 바꾸면 그것은 새로운 주장이다.**

2번은 내가 지어낸 설명("심이 억세다")과 지어낸 해법("잘게 썬다")이
실제 방법(세로로 반 가르기)으로 통째 교체됐다. 돌려깎기·보관 팁에 이어 세 번째다.

> **규칙**: 작성자가 준 표현이 범위·조건부이면 **그대로 유지**한다.
> 확정형으로 바꾸지 않는다. 방법과 이유는 작성자가 말한 것만 쓴다.

## C. 컴포넌트 타입을 잘못 지정한 것 — 1건

**훅 소제목은 `sectionTitle` 이다. `quotation` 이 아니다.**

과거 9편 중 7편이 `sectionTitle` 2개를 쓴다. 프로파일 §1에도 원래
`② 훅 소제목 sectionTitle 2줄` 로 적혀 있었는데, v8 재구성 때 내가 `quotation` 으로 바꿨다.

발행본에서는 훅이 서명 라인 text 블록 안으로 합쳐졌다.
붙여넣기 파일이 "인용구"라고 지시했으니, 인용구로 넣으면 세로줄 스타일이 되어
훅에 어울리지 않아 우회한 것으로 보인다. **내 표기 오류가 작성자의 수작업을 만들었다.**

### 함께 드러난 것 — 서명과 훅은 서로 다른 문구다

v14에서 나는 "서명 라인과 훅은 같은 문구를 한 줄/두 줄로 쓰는 하우스 패턴"이라고
단정하고 서명을 되돌렸다. **틀렸다.** 9편 실측:

| 서명 | 훅 |
|---|---|
| 저속노화 건강반찬 양배추샐러드_by링키 | 영양과 드레싱이 기가막힌 / 양배추샐러드 |
| 두부톳나물무침 톳요리 만드는 법_by징키 | 영양 만점 고소한 / 톳나물두부무침 |
| 가지구이무침 양념 레시피_by장키 | 가지구이 한다면 / 이 레시피 꼭 챙기세요 |
| 임짱 임성근셰프 무조림 직접해 봄_by링키 | 집에서 남대문 갈치조림맛을 낼 수 있다면? |
| 마녀스프 대용, 토달볶 활용법_by링키 | 재료 오직 3가지! / 무수분 토마토 스프 요리 |

**서명은 요리를 지칭하고, 훅은 다른 각도로 후킹한다.** 겹치는 경우가 오히려 예외다.
발행본도 `안 물러지게 데치는 오크라무침` / `데치기 2분이면 되는` + `오크라무침 레시피` 로
서로 다르게 썼다.

> v11에서 "중복"이라고 본 판단이 맞았고, v14에서 "하우스 패턴"이라며 되돌린 것이 틀렸다.
> 작성자가 지적한 것은 **톤앤매너**였는데(일기체) 나는 **중복 여부**로 잘못 읽었다.

## E. 작성자가 더한 것 — 새로 반영할 규격

### 9. 구분선을 섹션마다 넣는다 (3 → 11)

과거 9편의 HR 사용은 1, 1, 6, 1, 5, 1, 1, 6, 9 로 편차가 크지만
**최근으로 올수록 늘어난다.** 발행본 11개가 최다다.

배치 규칙 (발행본 실측):

```
[HR]  소제목 앞
[quotation]  질문형 소제목
[text/image] 답
[HR]  다음 절차 블록 앞
...
[text] 팁 1
[HR]
[text] 팁 2
[HR]
[text] 팁 3
[HR]
```

**팁 항목 사이에도 HR을 넣는다.** 성분표도 HR로 위아래를 감쌌다.

### 10. 빈 텍스트 블록으로 여백을 만든다 (0 → 3)

재료준비 블록 앞뒤 등에 내용 없는 `text` 컴포넌트를 넣어 간격을 준다.
과거 9편 중앙값 2개. 붙여넣기 파일에 `[빈 줄]` 로 표기해야 한다.

### 11. imageGroup 컴포넌트

사진 2장(된장·참기름)을 한 그룹으로 묶었다. 과거 9편에는 없던 신규 사용.
같은 단계의 사진 2장은 그룹으로 묶는 것을 기본으로 한다.

### 12. 소제목에서 키워드를 작은따옴표로 강조

```
초안    꼭지는 언제 자르나요?
발행본  '오크라 꼭지'는 언제 자르나요?
```

검색 키워드를 소제목 안에서 시각적으로 분리한다.

### 13. 제목 끝에 `!`

```
초안    오크라 데치는법, 커피포트 물로 2분이면 안 물러져요
발행본  오크라 데치는법, 커피포트 물로 2분이면 안 물러져요!
```

### 14. 본문을 더 쓴다 (1,490 → 2,054자)

내가 규격 하한(1,200자)에 맞춰 압축했는데, 실제로는 **중앙값 1,630자를 넘겨 썼다.**
설명을 자르는 방향이 아니라 채우는 방향이 맞다.
단계 4의 `아삭한 맛이 살아요` → `아삭한 맛과 매운향이 살아서 오크라와 잘 어울려요` 처럼
왜 그런지를 덧붙였다.

## 정리 — 앞으로의 기준 5가지

1. **작성자가 준 표현의 정밀도를 바꾸지 않는다.** 범위는 범위로 둔다.
2. **방법과 이유는 작성자가 말한 것만 쓴다.** 모르면 빈칸으로 두고 묻는다.
3. **프로파일에 적힌 표기를 임의로 바꾸지 않는다.** 바꾸려면 근거를 대고 확인받는다.
4. **미확정 제안을 초안에 기본값으로 넣지 않는다.**
5. **컴포넌트 타입을 정확히 지정한다.** 훅은 sectionTitle, 소제목은 quotation.
