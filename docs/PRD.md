## 1. 배경과 문제 정의

### 1.1 왜 지금인가

네이버 검색이 **AI 브리핑**과 **AI탭**으로 재편되고 있다. 사용자는 이제 원문을 처음부터
끝까지 읽지 않고 AI가 요약한 결과로 핵심을 파악한다. 이 구조에서 블로그의 가치는
"검색 결과 목록에 뜨는 것"에서 **"AI 답변에 인용되는 것"** 으로 이동한다.

네이버는 2026년 6월 창작자 펠로우십 **"네이버 메이트"** 를 시작하면서 선정 기준을
명시했다 — **"AI 브리핑 인용수를 중심으로"**. 즉 인용은 이제 측정되고 보상받는 지표다.

### 1.2 우리가 풀려는 문제

블로그를 두 사람(징키·링키)이 운영 중이다. 두 사람은 **자연식물식 중심의 식사**와
**꾸준하고 바른 운동법**을 통해 **건강한 여성의 삶**을 꾸려가는 것을 블로그의 축으로 삼는다.
글은 내돈내산·체험단·레시피·정보성·**운동** 5개 카테고리로 쓴다.

**태도**: 운영자의 말 그대로 — *"뭐가 답인지 우리는 몰라. 관심 갖고 고민하고 찾아가는
과정이야. 그걸 공유하는 거고."* 이 블로그는 **정답을 가르치는 채널이 아니라 탐구 과정을
공유하는 채널**이다. 이것은 취향이 아니라 **제품 사양**이다 —
단정형 조언 대신 과정형 서술을 기본 문체로 고정하고(원칙 6),
건강·의료 주장의 안전장치와도 맞물린다. 네이버가 우대하는
"직접 겪은 문제 해결 과정, 실패했던 경험, 시행착오"와도 정확히 같은 방향이다.

현재 방식의 병목:

| 병목 | 내용 |
|---|---|
| 반복 작업 | 매 글마다 서명 라인, 정보블록, 태그 확장, 고지문을 손으로 씀 |
| 규격 누락 | 체험단은 플랫폼별 반려 기준(사진 15장·배너·지도)을 매번 확인해야 함 |
| 최적화 부재 | AI 브리핑에 인용될 구조(직답·근거·비교)가 글마다 들쭉날쭉 |
| 사후 관리 없음 | 가격·영업시간이 바뀐 과거 글을 갱신하지 못함 |
| **형식 부담으로 발행 중단** | 매주 운동을 가르치는데 블로그에 못 올린다. 소재는 있으나 **서사로 바꾸는 비용**이 커서 멈춘다. 인스타에는 자주 올림 |

### 1.3 가장 중요한 제약 — 이것이 제품 방향을 결정한다

네이버는 공식 가이드에서 **명시적으로** 밝혔다:

> "사람이 직접 쓴 문장이 아닌 **AI가 기계적으로 생성·요약한 글을 무분별하게 발행하는 것은
> 지양**해 주세요." (콘텐츠 작성 가이드, 주의사항 1)
>
> "AI 도구를 사용했다고 해서 무조건 패널티를 받지는 않습니다. 다만 **진실된 경험은 오직
> 창작자만의 것**이므로, AI를 사용하더라도 최종 검토와 편집 단계를 거쳐 창작자님의
> 실제 경험과 지식을 콘텐츠에 잘 녹여내 주시는 것이 좋습니다." (FAQ 7)

**따라서 이 웹앱은 "AI 대필기"가 되어서는 안 된다.**
소재만 던지면 글이 나오는 도구를 만들면, 네이버가 걸러내겠다고 명시한 바로 그 콘텐츠를
대량 생산하게 된다. 단기 편의를 얻고 블로그 지수를 잃는다.

이 제품의 정체성은 **"경험 구조화기(Experience Structurer)"** 다.
사용자의 실제 경험 데이터를 강제로 입력받아, 그것을 네이버가 우대하는 구조로 조립한다.
AI는 문장을 다듬고 구조를 채우지만, **사실과 경험은 100% 사용자에게서 나온다.**

## 2. 제품 목표와 성공 지표

### 2.1 목표

1. 글 1편 작성 시간을 **절반 이하**로 줄인다 (규격·반복 작업 자동화)
2. 발행되는 모든 글이 **AI 브리핑 인용 요건**을 구조적으로 충족한다
3. 체험단 글의 **플랫폼 반려율 0%**
4. 블로그의 **주제 집중도(C-Rank)** 를 관리 가능한 상태로 만든다

### 2.2 성공 지표 (KPI)

| 구분 | 지표 | 목표 |
|---|---|---|
| 효율 | 글 1편 소요 시간 | 현재 대비 50% 이하 |
| 품질 | 발행 전 스코어카드 평균 | 80점 이상 |
| 노출 | AI 브리핑 인용 횟수 | 측정 시작 후 월 단위 증가 |
| 노출 | 검색 유입 비중 | 증가 추세 |
| CTR | 검색 노출 대비 클릭률 | 증가 추세 |
| 운영 | 체험단 반려 건수 | 0 |
| 자산 | 갱신된 과거 글 수 | 월 4편 이상 |

> **주의**: AI 브리핑 인용수는 네이버가 창작자에게 공개하는 지표가 아닐 수 있다.
> 측정 방법은 §12 미결정 사항 참조.

## 3. 근거 — 네이버 공식 기준 분석

### 3.1 두 개의 랭킹 축

네이버 블로그 검색은 **블로그 단위 신뢰도**와 **개별 글 품질**을 함께 본다.

| 축 | 공식 설명 | 제품에 주는 요구사항 |
|---|---|---|
| **C-Rank** | 출처 신뢰도. 관심사 집중도(Context) · 정보 품질(Content) · 소비 생산의 연쇄반응(Chain)을 종합해 창작자 신뢰도(Creator) 반영 | 주제가 분산되지 않도록 **카테고리 발행 비중을 추적·경고**해야 함 |
| **D.I.A.** | 키워드별 사용자가 선호하는 문서. 주제 적합도·경험 정보·정보 충실성·문서 의도·어뷰징 척도·독창성·적시성 반영 | **경험 정보와 독창성을 구조적으로 강제**해야 함 |
| **검색어 적합도** | 검색어가 문서 안에 나타나는 **빈도와 위치** 등, 문서와 검색어의 유사도가 적합도 산출에 반영 | 핵심 키워드의 **최소 배치 규칙**이 필요 (제목·도입·소제목·본문) |
| **최신성** | 기본 정렬은 관련도 순. **오래된 글도 관련도가 높으면 최신 글보다 앞설 수 있음** | 최신성은 주제별로 차등 적용. 무조건 새 글보다 **깊이 있는 글의 갱신**이 유효 |
| **노출 안정성** | 검색 순위는 지속적으로 변하며 **상위 고정 노출은 존재하지 않음** | 단발성 상위노출 기능(키워드 스터핑 등)은 설계에서 배제 |

핵심 함의 세 가지:

- **한 편 잘 쓰기(D.I.A.)와 주제 꾸준히 쌓기(C-Rank)는 별개다.** 제품은 둘 다 다뤄야 한다.
- 키워드는 **넣지 않는 것도 문제, 억지로 반복하는 것도 문제**다. 제품은 상한(스터핑 방지)만이 아니라
  **하한(최소 배치)** 도 함께 검사해야 한다. → §6.3 스코어카드
- 상위 고정 노출은 없다. 목표는 **시리즈·누적 신뢰·꾸준한 개선**이지 단발 상위노출이 아니다.

### 3.2 AI 브리핑 인용 5원칙 (공식)

| # | 원칙 | 공식 설명 요지 |
|---|---|---|
| 1 | **직접 경험한 지식** | 정보 수집을 넘어 직접 겪은 구체적 사례, 문제 해결 과정, 실패 경험, 상세 후기. 전문 주제는 통계·연구·공식 자료 인용 |
| 2 | **일관된 주제** | AI 검색 엔진은 특정 주제를 지속 발행하는 채널을 **'전문 출처'로 인식** |
| 3 | **거짓 없는 진정성** | 경제적 대가/내돈내산을 한눈에 알 수 있게 표시. 인용 시 원작자 밝히고 **원문 링크 삽입** |
| 4 | **읽기 쉬운 구조** | 제목·소제목·문단 나누기 활용. **미디어의 핵심 내용은 텍스트로도 함께 작성** |
| 5 | **최신성 유지** | 정보가 변경되면 **과거 글을 수정**하고 새 콘텐츠를 꾸준히 작성 |

### 3.3 콘텐츠 셀프 체크 5항목 (공식 실전편)

이것이 **스코어카드의 뼈대**가 된다.

| # | 항목 | 체크 질문 (공식) |
|---|---|---|
| 1 | **독자 및 목적** | 누가, 언제, 어떤 상황(TPO)에서, 어떤 목적으로 이 정보를 찾는지 독자 관점에서 썼는가 |
| 2 | **절차 및 구체적 해결 과정** | 실제 경험한 순서와 절차를 상세히 기술했는가 / 창작자만 아는 팁·주의사항을 포함했는가 |
| 3 | **대안 및 비교 분석** | 고려한 대안과 선택의 결정적 이유, 각 대안의 장단점을 담았는가 / 상황별 최적 선택 기준을 설명했는가 |
| 4 | **실제 적용 사례 및 결과** | 적용 결과·예상과 달랐던 점·시행착오를 담았는가 / 통계·연구·공식 문서 등 객관적 근거를 인용했는가 |
| 5 | **맥락에 맞는 이미지·동영상** | 인포그래픽·과정 설명 이미지가 적재적소에 있는가 / **멀티미디어 내용을 텍스트로도 제공**했는가 |

### 3.4 Good vs Bad (공식 예시에서 추출한 판정 기준)

| 항목 | Good | Bad |
|---|---|---|
| 독자 | "회의 30분 전 식사를 마쳐야 하는 직장인"처럼 **독자·상황을 특정**하고 동선·가격·소요시간 제공 | 순위만 나열, 누가 어떤 상황에서 볼지 없음 |
| 절차 | "1~30일, 31~60일" 시간순 + **구체적 수치**(페이스 7분→6분 30초) | 일반론과 근거 없는 주장("매일 30분이면 한 달에 5kg") |
| 비교 | A·B·C 직접 써보고 항목별 비교, **상황별 선택지**("커플엔 A, 가족여행엔 B") | "전망 좋고 가격도 합리적" 류 누구나 쓸 수 있는 일반론 |
| 결과 | "고양이 2마리, 3개월 교차 사용"처럼 **환경·기간 명시** + 직접 측정값(소음 dB 등) | 제조사 스펙시트 복사 + 구매 링크만 강조 |
| 미디어 | 표·리스트·소제목으로 구조화, 본문과 직접 관련된 사진 | 본문과 무관한 이미지 삽입 |

> **관찰**: Good Case의 공통점은 전부 **숫자와 조건**이다. 기간, 수치, 사용 환경, 상황.
> 스코어카드는 이 "정량 신호"의 존재 여부를 기계적으로 검사할 수 있다.

### 3.5 금지 행위 (공식)

| # | 금지 | 제품 대응 |
|---|---|---|
| 1 | 무분별한 복제와 생성 / **AI가 기계적으로 생성·요약한 글** | 경험 입력 없이는 생성 자체를 막는다 |
| 2 | 과도한 광고·홍보, **외부 URL 과다 삽입** | URL 개수 상한 경고 |
| 3 | **무관한 키워드 삽입** | 키워드 **상한** 검사 (문단당 1회). 단 타깃 질의 키워드는 **하한**도 검사 |
| 4 | 콘텐츠와 무관한 이미지·동영상 | 사진마다 어떤 섹션에 쓸지 지정하게 함 |
| 5 | 부정확·부적절한 정보 | 사실 항목에 출처·기준일 필수 |

추가로 네이버 안내에 명시된 것:
- 협찬·대가성 표기 **혼용이나 누락**은 다른 정상 게시물에도 불리하게 작용
- 제목·닉네임에 광고성 키워드 과다, **하루 과다 발행**은 어뷰징 판단 위험
- 검색 노출을 원하면 **전체 공개 + 검색 허용** 상태여야 하고, 반영에 **최대 24시간**

### 3.6 AI 브리핑 관련 FAQ에서 뽑은 핵심

| 질문 | 답변 요지 | 제품 함의 |
|---|---|---|
| C-Rank가 인용에 영향을 주나 | **그렇다.** 기존 검색에 잘 노출되는 양질의 글이 인용될 가능성이 높음. 특정 주제를 꾸준히 써온 채널이 더 자주 인용 | 검색 최적화와 AI 최적화는 **분리된 목표가 아니다** |
| 광고·협찬 글도 인용되나 | **무조건 배제되지 않음.** 단 경제적 이해관계를 명확히 명시해 투명성 확보가 중요. 홍보 멘트로만 가득하면 불리 | 체험단 글도 인용 대상. 고지 + 실질 정보가 관건 |
| 최근 글이 더 인용되나 | 실시간·트렌드 주제는 최신 글 우대. **시간이 지나도 변하지 않는 정보는 깊이와 구조적 완성도가 더 중요** | 최신성은 주제별로 다르게 적용 |
| 이미지 관련 | **이미지의 핵심 정보를 텍스트로 함께 작성해야 인용에 유리** | 사진 캡션·대체 텍스트를 강제 |

### 3.7 AI탭이 시사하는 것

AI탭은 **네이버 블로그·카페 UGC를 근거로** "음식의 맛, 식당의 분위기, 상품 후기, 여행 꿀팁"
같은 **현장감 있는 알짜 정보**를 요약해 답한다. 또한 "좌석 간격이 적당하고 음악 소리가
크지 않은 카페", "이어컵이 부드럽고 압박감이 적은 헤드폰"처럼 **속성 단위 질의**를 처리한다.

> **함의**: 우리 글에 **속성 단위 사실**(좌석 간격, 소음, 콘센트 유무, 무게, 착용감)이
> 텍스트로 박혀 있어야 AI탭 답변의 근거로 뽑힌다. 이건 이미 우리가 쓰는 `●` 정보블록의
> 확장판이다. → **속성 체크리스트**를 서브카테고리별로 제공한다.

## 4. 전략 — 3개의 레버

### 레버 1. 블로그 지수 (C-Rank)

**핵심: 주제 집중도.** 잡블로그가 아니라 전문 출처로 인식되어야 한다.

| 실행 | 제품 기능 |
|---|---|
| 카테고리 발행 비중 관리 | 대시보드에 최근 3개월 카테고리 분포 표시, 편중 이탈 시 경고 |
| 발행 간격 관리 | 하루 과다 발행 방지. 예약 발행으로 분산 |
| 시리즈화 | 같은 주제 글끼리 상호 링크 제안 |
| 기존 글 갱신 | 최신성 유지 → §6.5 리프레시 큐 |

> **블로그 구조가 이미 유리하다.** 전체 1,045편 중 `건강한 집밥생활`이 351편으로 약 3분의 1을
> 차지하고, 여기에 `차생활` · `자연식물식 하는법` · `운동코치 링키T`가 같은 방향으로 묶인다.
> **"건강한 먹거리 + 몸"** 이라는 축이 명확하므로, C-Rank 관심사 집중도 측면에서 좋은 상태다.
> 대시보드는 이 축에서 벗어나는 소재의 비중을 추적하고 경고한다.
> 전체 카테고리 트리와 매핑 규칙은 `docs/naver-category-map.md`.

### 레버 2. 클릭률 (CTR)

검색 결과에 떠도 안 눌리면 무의미하다. D.I.A.는 사용자 선호를 반영하므로 CTR은 순위에도
되먹임된다.

| 실행 | 제품 기능 |
|---|---|
| 제목 A/B 후보 생성 | 실측 공식(§내돈내산 §3) 기반 후보 3~5개 + 선택 |
| 검색 결과 미리보기 | 제목·썸네일·요약이 검색 결과에서 어떻게 보이는지 시뮬레이션 |
| 궁금증 키워드 배치 | 웨이팅·주차·가격·장단점 등 실제 검색 의도를 제목에 |
| 썸네일 가이드 | 대표 이미지 선택 시 텍스트 가독성 체크 |

> 낚시성 제목은 금지 행위에 해당하므로, **본문이 답하지 못하는 내용을 제목에 넣으면
> 스코어카드에서 감점**한다.

### 레버 3. AI 브리핑 인용

**핵심: 인용 가능한 단위(citable unit)를 글 안에 심는다.**

AI가 인용하려면 그 문장이 **자립적으로 사실을 진술**해야 한다. "정말 맛있었어요"는 인용
불가, "메밀 콩국수 11,000원, 국물 농도는 진한 편"은 인용 가능.

| 인용 단위 | 형태 | 이미 하고 있는가 |
|---|---|---|
| 구조화 사실 | `●` 정보블록 (위치/영업시간/주차) | **O** — 유지·강화 |
| 가격 + 단위 환산 | `6칩에 33,000원 (잔당 5,500원)` | **O** — 유지 |
| 속성 사실 | 좌석 간격, 소음, 콘센트, 무게 | △ — **속성 체크리스트로 강화** |
| 직답 문장 | 첫 문단의 결론 한 줄 | X — **신규** |
| 비교 표 | 대안 A/B/C 장단점 | X — **신규** |
| 요약 불릿 | 좋았던 점/아쉬운 점/추천 대상 | X — **신규** |
| 출처 링크 | 인용 시 원문 링크 | X — **신규** |
| 기준일 | "2026년 8월 기준" | X — **신규** |

## 5. 제품 원칙

이 5가지는 기능 우선순위를 다툴 때의 판정 기준이다.

1. **경험 없이는 생성 없다.** 사용자가 실제 경험 데이터를 입력하지 않으면 글을 만들지 않는다.
   소재만 주면 글이 나오는 경로는 제공하지 않는다.
2. **사실은 사용자에게서, 문장은 AI에게서.** AI가 가격·영업시간·수치를 지어내지 못하게
   입력 필드로 분리한다. 생성문에 미입력 사실이 등장하면 차단한다.
3. **규격은 자동, 판단은 사람.** 서명·고지문·태그·배너 같은 규격은 자동화하고,
   무엇을 쓸지·발행할지는 사람이 정한다. 기본 동작은 **초안 저장**이다.
4. **한 편의 완성도 > 편수.** 대량 발행 기능을 만들지 않는다. 어뷰징 판정 위험이 크고
   C-Rank에 해롭다.
5. **하우스 보이스를 지킨다.** 이모지 없음, 18~22자 줄바꿈, 해요체 70% + 습니다체 25%.
   최적화를 이유로 이 규격을 깨지 않는다.
6. **단정하지 않는다.** 정답을 선언하는 대신 시도와 결과를 서술한다
   (`이렇게 하세요` → `이렇게 해봤더니 이랬어요`). 건강·의료 주제에서는 **강제 규칙**이며,
   개인 경험임을 명시한다. 이것이 블로그의 태도이자 법적 안전장치다.

## 6. 기능 요구사항

### 6.1 경험 캡처 (Experience Capture) — 제품의 심장

가장 중요한 화면. 사용자가 **경험을 구조화된 데이터로** 남긴다.

**FR-1.1 공통 입력**

| 필드 | 필수 | 비고 |
|---|---|---|
| 카테고리 | ★ | 내돈내산 / 체험단 / 레시피 / 정보성 / 운동 |
| 서브카테고리 | ★ | 카테고리별 §스타일 프로파일 참조 |
| 대상명 | ★ | 상호·제품명 |
| **타깃 검색 질문** | ★ | **이 글이 답하려는 검색 질문을 한 문장으로.** 아래 설명 참조 |
| 방문·사용 일시 | ★ | 기준일 표기와 최신성 판단에 사용 |
| 사진 | ★ | 15장 이상 권장(체험단은 필수). 각 사진에 **섹션 지정 + 한 줄 설명** |
| 한 줄 결론 | ★ | 첫 문단 직답에 그대로 사용 |

**타깃 검색 질문(Target Query)** — 가장 먼저 묻는 필드로 둔다.

> 예: "망원동에서 노트북 작업하기 좋은 조용한 카페 있나?"
> "프라우허 오늘보틀 텀블러 결로 심한가?"

이 한 문장이 글 전체의 기준점이 된다. 제품은 이것을 네 곳에 쓴다:

| 쓰임 | 방식 |
|---|---|
| 제목 후보 생성 | 이 질문에 답하는 형태로 후보를 만든다 |
| 첫 문단 직답 | "한 줄 결론"이 이 질문의 답이 되는지 검사 |
| 소제목 배치 | 질문을 쪼갠 하위 질문을 소제목으로 (AEO) |
| 낚시성 검사 | **제목이 약속한 질문에 본문이 답하지 못하면 차단** |

> 근거: 네이버 검색어 적합도는 "검색어가 문서 안에 나타나는 빈도와 위치"를 본다.
> 타깃 질의를 먼저 정하면 키워드를 억지로 뿌리지 않고도 제목·도입·소제목에 자연스럽게 배치된다.

**FR-1.2 셀프 체크 5항목 입력** — 네이버 공식 체크 항목을 **입력 폼으로 전환**한다.

| 입력 | 대응 원칙 | 미입력 시 |
|---|---|---|
| **독자·상황(TPO)** — 누가, 언제, 어떤 상황에서 | 셀프체크 1 | 경고 (감점) |
| **절차·과정** — 시간 순서, 창작자만 아는 팁·주의사항 | 셀프체크 2 | 경고 |
| **대안 비교** — 고려한 대안, 선택 이유, 상황별 추천 | 셀프체크 3 | 경고 |
| **결과·시행착오** — 예상과 달랐던 점, 아쉬운 점 | 셀프체크 4 | **차단** (경험 없이는 생성 없다) |
| **객관적 근거** — 통계·공식 자료 + 원문 링크 | 셀프체크 4 | 선택 |

**FR-1.3 속성 체크리스트** — 서브카테고리별로 AI탭이 물어볼 만한 속성을 미리 제시하고
해당하는 것만 채우게 한다.

```
[카페]  좌석 간격 · 콘센트 · 소음 수준 · 와이파이 · 1인석 · 이용시간 제한 · 반려동물
[식당]  대기 시간 · 1인 방문 가능 · 주차 · 좌석 수 · 아이 동반 · 포장
[제품]  무게 · 크기 · 소재 · 배터리 · 세척 · 소음 · 호환성
[식품]  용량 · 칼로리 · 원재료 · 알레르기 · 보관 · 조리 시간
```

> 이 값들이 **본문 텍스트와 `●` 정보블록에 동시에 반영**된다. (미디어 핵심 내용을
> 텍스트로도 제공하라는 원칙 4 충족)

**FR-1.4 카테고리별 추가 입력**
- **체험단**: 플랫폼 / 업체명 / 대가 유형 / 필수 키워드 / 필수 URL / 캠페인 배너
  (→ `docs/style-profile-chehumdan.md` §4)
- **운동**: 서브카테고리(수련일지 / 수업소개안내 / 워크샵후기).
  수련 일지는 일자별 기록을 원문 그대로 받고 하우스 보이스를 적용하지 않는다
  (→ `docs/style-profile-training.md` §2.3)
- **내돈내산**: 실제 지출 금액, 재방문 의사
- **레시피**: 재료·계량, 조리 단계, 조리시간·인분, 실패 지점
- **정보성**: 서브카테고리별 섹션. 건강 주장이면 **출처(기관명·연도·링크) 필수**
- **운동**: 프로파일 미작성. 샘플 수집 후 확정 (§12)

### 6.1.5 인스타그램 → 블로그 변환 (운동 카테고리 핵심)

**FR-1.5** 병목이 소재가 아니라 **형식**인 경우를 위한 진입 경로다.
매주 수업은 하는데 블로그에 못 올리는 상황이 여기 해당한다.

> 참고: 수련 일지 본문에 *"매일 오전 타임랩스로 기록하고 인스타그램에 스토리로 게시하고
> 있습니다. 그것을 캡처한 것을 바탕으로 기록해 볼게요"* 라고 적혀 있다.
> **인스타 → 블로그 파이프라인이 수동으로는 이미 존재한다.** 이걸 자동화한다.

**FR-1.5.1 입력** — 아래 중 하나 이상

| 입력 | 형태 |
|---|---|
| 인스타 게시글 캡션 | 텍스트 붙여넣기 |
| 인스타 스토리 캡처 | 이미지 업로드 |
| 사진·영상 | 수업 사진, 타임랩스 캡처 |
| 키워드만 | "고관절 외회전, 아기 발달 움직임, 3주차" |
| 음성 메모 | (선택) 수업 직후 녹음 |

**FR-1.5.2 부족한 정보 질문** — 인스타 캡션은 짧고 맥락이 생략돼 있다.
그대로 늘리면 알맹이 없는 글이 되므로, **질문으로 채운 뒤 생성**한다.
이것이 원칙 1을 지키는 방식이다.

- 어떤 수업이었나 (장소·인원·주차)
- 무엇을 다뤘나 (동작·부위)
- **잘 안 됐던 것 / 발견한 것** ← 필수. 미입력 시 생성 차단
- 참여자 반응 중 기억에 남는 것

**FR-1.5.3 주간 수업 기록 템플릿** — `{n}주차 수업 기록` 시리즈.
인스타 스토리 몇 장 + 질문 답변 5개면 한 편이 완성되도록 한다.
상세는 `docs/style-profile-training.md` §4.4.

**FR-1.5.4 고정 자산 자동 삽입** — 수업 장소·형태·가격·문의 경로·인스타 계정은
설정에 저장해두고 매번 자동으로 넣는다. 타이핑하지 않는다.
값은 `docs/style-profile-training.md` §3.3. 연락처는 **카카오톡 `cutielee`,
인스타 `cutie._.lee`, 전화 010-8910-0713** 로 통일한다.

> **연동 방식**: 인스타 API 연동은 제약이 크므로 **캡션 붙여넣기 + 이미지 업로드**를
> 기본으로 한다. 자동 수집은 후순위.

### 6.2 생성 엔진

**FR-2.1** 하우스 보이스 규격(스타일 프로파일)과 경험 캡처 데이터를 결합해 SE 컴포넌트
구조의 초안을 생성한다.

**FR-2.2 사실 고정(Fact Pinning)** — 가격·시간·수치·주소는 **입력값을 그대로 삽입**하며
LLM이 바꾸지 못한다. 생성 후 검증기가 원본 입력과 대조해 불일치 시 차단한다.

**FR-2.3 인용 단위 자동 배치**
- 첫 문단에 "한 줄 결론" 직답
- `●` 정보블록 (장소형)
- 대안 비교 표 (입력이 있을 때)
- 클로징 직전 요약 불릿 3줄 (좋았던 점 / 아쉬운 점 / 추천 대상)
- 가격 옆 기준일 표기
- 인용 자료의 원문 링크

**FR-2.4 제목 후보 생성** — 실측 공식 기반 3~5개. 각 후보에 예상 검색 의도 표시.

**FR-2.5 태그 확장** — 브랜드 축 롱테일 확장. 카테고리별 개수 규격 준수.

### 6.3 품질 게이트 — 발행 전 스코어카드

**FR-3.1** 발행 전 100점 만점 스코어를 산출하고, 미달 항목을 구체적으로 지적한다.

| 영역 | 배점 | 검사 항목 |
|---|---|---|
| **경험 신호** | 25 | 독자·TPO 명시 / 시간순 절차 / 창작자만 아는 팁 / 시행착오·아쉬운 점 |
| **정량 신호** | 20 | 숫자가 담긴 문장 수 / 가격·기간·수치·환경 조건 명시 / 기준일 |
| **구조** | 15 | 소제목 수 / 질문형 소제목 비율 / 첫 문단 직답 / 요약 불릿 / 문단 길이 |
| **투명성** | 15 | 대가성 고지(체험단) 또는 내돈내산 표기 / 인용 출처 링크 |
| **검색어 적합도** | 10 | 타깃 질의 키워드가 **제목·도입·소제목·본문**에 배치되었는가 (하한 검사) |
| **미디어** | 10 | 사진 수 / 사진별 텍스트 설명 / 본문 무관 이미지 없음 |
| **주제 연결성** | 5 | 이 글이 블로그 핵심 주제 축과 연결되는가 (C-Rank) |
| | **100** | |

**FR-3.2 감점·차단 항목**

| 사유 | 처리 |
|---|---|
| 시행착오·아쉬운 점 미입력 | **차단** |
| 대가성 고지 누락(체험단) | **차단** |
| 사실 불일치(입력값과 본문) | **차단** |
| 제목이 약속한 내용을 본문이 답하지 않음 | **차단** (낚시성) |
| **타깃 질의 키워드가 제목 또는 도입에 없음** | 감점 (하한 미달) |
| 같은 키워드가 한 문단에 2회 이상 | 감점 (상한 초과) |
| 외부 URL 과다 | 감점 |
| 이모지 사용 | 감점 (하우스 보이스 위반) |
| 사진 15장 미만 | 경고(내돈내산) / **차단**(체험단) |

**FR-3.3 체험단 플랫폼 체크리스트** — `docs/style-profile-chehumdan.md` §9의 8개 항목.

### 6.4 발행

**FR-4.1** 기본 동작은 **초안 저장**. 발행·예약 발행은 명시적 선택.
**FR-4.2** 카테고리 지정, 태그 삽입, 공개 범위 = 전체 공개 + 검색 허용(강제).

**FR-4.2.1 네이버 카테고리 자동 추천** — 블로그에 26개 카테고리가 있고, 우리 카테고리와
**1:1 대응이 아니다**(같은 내돈내산도 소재에 따라 외식 리뷰/차생활/간식 리뷰로 갈림).
서브카테고리 + 소재로 **1순위와 대안 1~2개를 제시**하고 사용자가 확정한다.
규칙은 `docs/naver-category-map.md` §4. 사용자가 1순위와 다르게 고르면 **선택 이력을 저장**해
다음부터 반영한다. 레시피는 재료에 동물성 재료가 있는지로 집밥/채식을 **자동 판정**할 수 있다.
**FR-4.3** 발행 후 **최대 24시간** 반영 대기임을 안내하고, 반영 여부를 확인할 수 있게 한다.
**FR-4.4** 체험단은 발행 후 **플랫폼에 링크 제출**해야 미션이 완료됨을 리마인드한다.
**FR-4.5** 하루 발행 편수 상한을 두고 초과 시 예약 발행을 권한다.

### 6.5 사후 관리 — 리프레시 큐

원칙 5(최신성)를 실행하는 기능. **경쟁 블로그가 잘 안 하는 영역이라 차별점이 크다.**

**FR-5.1** 발행한 글의 **사실 데이터**(가격·영업시간·주차·스펙)를 DB에 보관한다.
**FR-5.2** 일정 기간(기본 6개월) 경과 시 검증 대상으로 큐에 올린다.
**FR-5.3** 장소형은 네이버 플레이스 정보와 대조해 **변경 의심 항목**을 표시한다.
**FR-5.4** 갱신 시 본문의 해당 사실과 기준일을 함께 수정한다.

### 6.6 채널 관리 (C-Rank 대시보드)

**FR-6.1** 최근 3·6·12개월 카테고리별 발행 비중 시각화.
**FR-6.2** 주제 축(먹고 마시기 + 차·그릇)에서 벗어난 글의 비중 경고.
**FR-6.3** 발행 간격 분포. 하루 몰아쓰기 감지.
**FR-6.4** 체험단 글 비중 경고 — 대가성 글이 과다하면 정상 게시물에도 불리.
**FR-6.5** 시리즈 링크 제안 — 같은 주제 과거 글과 상호 링크.
**FR-6.6** **글 단위 주제 연결성 검사** — 발행 전에 "이 글이 블로그 핵심 주제 축과 연결되는가"를
스코어카드에서 확인한다. 채널 대시보드(사후)만으로는 늦다.

## 10. 로드맵

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| **M0** 기반 | 스타일 프로파일 4종 + 카테고리 매핑 | **완료** — 프로파일 4개, 카테고리 지도 1개 |
| **M0.5** 확장 | 운동 카테고리 프로파일 | **완료** — 일지 11편 + 수업안내 4편 분석 |
| **M1** 코어 | 경험 캡처 + 생성 + 스코어카드 + 초안 저장 | 내돈내산 글 1편을 앱으로 초안까지 |
| **M2** 체험단 | 플랫폼 규격·배너·고지문·체크리스트 | 체험단 글 반려 없이 발행 |
| **M3** 최적화 | 제목 후보·검색 결과 미리보기·태그 확장 | CTR 측정 시작 |
| **M4** 자산화 | 리프레시 큐 + C-Rank 대시보드 | 과거 글 갱신 워크플로 가동 |

> M1까지가 최소 가치 제품(MVP)이다. M4가 장기 차별점이다.

## 11. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 비공식 발행 API 스키마 변경 | 발행 불가 | 어댑터 격리, 초안 저장 우선 |
| 로그인 캡차·2FA | 자동화 중단 | 최초 수동 로그인 후 세션 재사용 |
| 봇 탐지·계정 제재 | 치명적 | 상호작용 자동화 배제, 빈도 제한, 사람 검수 |
| **AI 생성 글로 판정** | C-Rank 하락 | **제품 원칙 1·2로 구조적 방지** — 경험 입력 강제, 사실 고정 |
| 대가성 표기 누락·혼용 | 정상 글에도 불리 | 고지문 자동 삽입 + 발행 차단 |
| 스코어 만점을 노린 형식주의 | 글이 기계적으로 변함 | 스코어는 **가이드**이지 목표가 아님. 감점 허용 |

> 마지막 항목을 강조한다. 스코어카드가 높다고 좋은 글이 아니다. 네이버 스스로
> "모든 항목이 우수하다고 해서 검색에 반드시 상위로 랭크되지 않는다"고 밝힌다.
> 스코어는 빠뜨린 것을 알려주는 체크리스트로만 쓴다.

## 12. 미결정 사항

1. **AI 브리핑 인용수 측정 방법** — 네이버가 창작자에게 이 지표를 공개하는지 확인 필요.
   네이버 메이트 선정 기준이라고 밝힌 만큼 어떤 형태로든 제공될 가능성이 있다.
   불가하면 대리 지표(검색 유입, 노출수)로 대체한다.
2. **움직임 워크샵 후기 샘플** — 0편. 현재는 내돈내산 장소형 규격으로 대체 중
3. **기술 스택** — 발행 모듈은 Node(Playwright)가 유리. 웹앱 전체를 Next.js 단일 스택으로
   갈지, 프론트/백 분리할지
4. **자체 고지 배너 이미지** 제작 및 등록
5. **레뷰 캠페인 가이드 원문 샘플** — 파싱 규칙 설계용
6. **여성건강 카테고리** — 아직 발행 이력이 없다. 건강 상식형 프로파일을 그대로 쓰되
   여성 건강 주제일 때 이 카테고리로 배정하는 것으로 잠정 처리했다.
