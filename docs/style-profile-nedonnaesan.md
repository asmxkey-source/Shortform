## 1. 문서 골격

> **이 절은 `docs/document-structure-spec.md` 를 상속한다.**
> 공통 3법칙(서론 3문장 / 핵심 정보 블록을 앞에 / 해석·배경은 뒤로),
> 표준 시퀀스, 발행 전 점검 6항목은 그 문서에 있다.

```
① 서명 라인      text          "{한 줄 요약}_by{징키|링키}"          ← 100% 고정
② 훅 소제목      quotation     2~4줄
③ 구분선         horizontalLine
④ 서론           text          3문장. 방문·구매 계기 + 결론 선제시
⑤ 대표 이미지    image          공간 전경 또는 제품 사용 모습 (썸네일)
⑥ 정보블록 ★    quotation     아래 서식
⑦ [지도]         map           장소형만. 정보블록 다음에 온다
⑧ 본문 섹션      ── 4~7회 반복 ─────────────────────────
                 quotation     질문형 소제목
                 image         1~3장
                 text          3~7줄
                 ────────────────────────────────────
⑨ 후기 & 팁 ★   quotation     "{대상} 후기 & 팁" + 번호 2~4개
⑩ 클로징         text          총평 3~4줄
⑪ [배너 이미지]  image
```

### ⑥ 정보블록 (필수) — 가격대·대표메뉴 추가

기존 `● 위치 / ● 운영시간 / ● 주차 / ● 그 외` 에서 **두 항목을 추가한다.**
검색 의도의 핵심인데 빠져 있었다.

```
● 위치      서울 마포구 …
● 영업시간  09:00~19:00 (매주 월요일 휴무)
● 주차      건물 뒤 2대. 인근 공영주차장 도보 3분
● 가격대    커피 5,000~6,500원 / 디저트 7,000원대
● 대표메뉴  화이트 라떼, 핸드드립
● 그 외     콘센트 6자리, 노트북 가능
```

물건형은 `● 제품명 / ● 가격 / ● 구입처 / ● 사용 기간` 으로 바꾼다.

> **시간 표기 정규화**: `09:00~19:00` 형식으로 통일한다(물결). 하이픈 혼용 금지.
> 원문에서 두 표기가 섞여 있었다.

### 순서를 바꾼 이유

기존 골격은 `대표이미지 → 지도 → 정보블록` 이었다. 지도는 이미지 카드라
텍스트로 인용되지 않는다. **정보블록을 먼저 두어야 AI가 인용할 수 있다.**

### 제목에서 내린 것

웨이팅·주차·가격·장단점을 제목에 나열하던 습관은 폐기했다(§3).
이 항목들은 **질문형 소제목**으로 내린다.

```
○  주차는 어디에 하나요?
○  웨이팅 얼마나 걸리나요?
○  혼자 가도 괜찮은가요?
○  콘센트 자리는 몇 개인가요?
```

**섹션 수**: 소제목 4~8개 (중앙값 5). 그중 질문형 60% 이상.
**이미지 비율**: 전체 컴포넌트의 30~35%. 텍스트 블록과 거의 1:1 교차.

## 2. 어투·문체## 2. 어투·문체 (하우스 보이스 규격)

### 2.1 종결어미 — 9편 986줄 실측

| 어미 | 비율 | 비고 |
|---|---|---|
| `~어요/아요/에요/예요/해요` | **약 70%** | 주력. 해요체 |
| `~습니다/ㅂ니다` | **약 25%** | 단락 마지막 줄, 정보 전달 문장에 배치 |
| `~는데요/인데요/거든요/고요/죠` | 약 5% | 연결·완충용 |

> **규칙**: 기본은 해요체. 문단의 **마지막 줄**이나 스펙·사실 전달 문장에 `~습니다`를 섞어
> 톤을 눌러준다. 한 문단 안에서 두 체가 섞이는 것이 이 블로그의 특징이므로 통일하지 말 것.

### 2.2 화자와 호칭

- 1인칭: **저** (우리 X, 필자 X)
- 독자 호칭: **이웃님들**, `~하는 분들`, `~신 분들께`
- 인사말: `안녕하세요 이웃님들!` / `안녕하세요!` — **약 30%만 사용**. 나머지는 인사 없이
  바로 계기 문장으로 시작 (예: "강릉으로 혼자 여행 갔다가", "흑백요리사 1, 2를 재밌게 봤습니다.")
- 두 사람 공동 운영이라 본문에 `링키징키`가 주어로 등장하기도 함

> **작성자별 톤 구분은 하지 않는다.** 징키/링키의 종결어미 분포를 실측한 결과 유의미한
> 차이가 없었고(둘 다 `~어요` 7%대 주력), 목적이 AEO/GEO 검색 노출이므로 **하나의 통합
> 하우스 보이스**로 생성한다. 이름은 아래 §2.6 서명 라인에서 **발행 시점에 선택**만 한다.

### 2.6 서명 라인 (발행 시 작성자 선택)

본문 **최상단 첫 텍스트 블록**에 고정으로 들어가는 한 줄:

```
{한 줄 요약}_by{징키|링키}
```

실제 예: `망원동 조용한 카페 물루_by징키`, `프라우허 텀블러 내돈내산 리뷰_by링키`

- 9편 전부 이 형식을 지킴 (100% 고정)
- `_by` 앞뒤 공백 없음
- 한 줄 요약은 제목의 축약형 (10~20자)
- 같은 텍스트 블록 안에서 줄바꿈 후 2~4줄 훅이 이어짐

> **웹앱 요구사항**: 생성 마지막 단계에서 **"누구로 발행할까요?"** 를 묻고
> `징키` / `링키` 중 선택받아 서명 라인에 바로 치환해 넣는다. 톤은 바뀌지 않고
> 이름만 들어간다.

### 2.3 이모지 — **쓰지 않는다**

9편 전체에서 이모지 사용 **0회**. 특수문자는 아래만 사용:

- `●` — 정보블록 대항목 (23회)
- `·` — 정보블록 하위 항목
- `ㅋㅋ` — 아주 드물게 (2회). 기본은 쓰지 않음
- `!` — 제목과 클로징에 제한적으로
- 스티커(sticker) 컴포넌트는 사용 — 이모지 대신 네이버 스티커로 감정 표현

> **생성 규칙: 이모지 절대 삽입 금지.** 😊🍽✨ 류를 넣으면 하우스 보이스가 깨진다.

### 2.4 줄바꿈과 분량

| 항목 | 값 |
|---|---|
| **한 줄 길이** | 중앙값 **18자** (13~23자). 40자 넘으면 안 됨 |
| 텍스트 블록당 줄 수 | 3~8줄 (중앙값 5) |
| 본문 총 글자수 | **1,600~2,600자** (중앙값 2,020자) |
| 이미지 | 10~23장 (중앙값 14장) |

> 모바일에서 읽기 좋게 **의미 단위로 강제 개행**한다. 문장이 길면 중간에서 끊어 다음 줄로.
> 이것이 이 블로그의 가장 눈에 띄는 시각적 특징이다.

### 2.5 문장 습관

- 구어체 축약: `사봄`, `맛봄`, `~해버림`, `~네요` 등 서술을 끊는 명사형 종결을 섹션 훅에 사용
- 솔직한 단점 명시: "제일 논란이 되고 있는 단점 정리", "구매 전 필독! 솔직 호불호"
- 자문자답형 소제목: `~한 곳일까?`, `맛은?`, `괜찮네`, `그러나?`

### 띄어쓰기 없는 복합 키워드 — 조건부 유지

`합정혼밥점심맛집` 같은 결합은 검색 매칭에는 유리하나 **읽기 어렵다.**
공식 가이드는 "읽기 쉬운 구조"를 원칙으로 두므로 다음 선에서 쓴다.

- **2개 결합까지만** 허용: `합정혼밥`, `성수소품샵` (○) / `합정혼밥점심맛집` (✕)
- 앞 15자 안에서만 사용

### `내돈내산` 표기

제목에 쓸 수 있다. 공식 가이드 원칙 3(거짓 없는 진정성)이 요구하는
경제적 이해관계 표시에 해당하므로, 신호어가 아니라 **투명성 표시**로 분류한다.

> **v2 정정 기록** — 기존 규격은 과거 글 9편에서 역산한
> `{지역}+{대상}+{부가키워드 2~3개}+{후기/추천 신호어}` 공식이었다.
> 부가 키워드 나열이 네이버가 배제하는 "반복적인 키워드 나열"에 해당해 폐기했다.
> 웨이팅·주차·가격 같은 항목은 제목에 나열하는 대신 **질문형 소제목**으로 내린다.
> (`주차는 어디에 하나요?`, `웨이팅 얼마나 걸리나요?`) 인용 단위로도 그쪽이 유리하다.

## 5. 정보블록 (SEO·AEO·GEO 공통 자산) — 장소형 필수

실제 포맷 그대로 유지한다:

```
● 위치
· 6호선 망원역 1번 출구에서 396m (도보 10분)
● 운영시간
· 월~수, 금 09:00~19:00
· 토, 일, 공휴일 11:00-19:00
· 정기휴무 매주 목요일
· 033-652-6701
● 주차
· 주차 어려움
● 그 외 사항
· 메인 메뉴 1인 1식 주문 필수
· 이용시간: 최대 2시간
```

**항목 순서**: 위치 → 운영시간 → 주차 → 그 외 사항 → [인스타그램/사이트]
**위치 표기**: `<역명> <번>출구에서 <거리>m` 또는 `도보 <n>분` — 검색 질의와 직접 매칭됨

> 이 블록은 그대로 **AEO/GEO 자산**이다. 답변엔진과 LLM이 "영업시간?", "주차 되나요?"에
> 바로 인용할 수 있는 구조화된 사실이므로, 자동화에서도 **반드시 생성**하고 형식을 유지한다.

### 가격 표기

- 항상 `11,000원` 형식 (천단위 콤마 + 원)
- 소제목에 가격을 직접 넣는 패턴 있음: `주문 메뉴: 메밀 콩국수 가격: 11,000원`
- 단위당 환산까지 제시: `6칩에 33,000원 (잔당 5,500원)` ← GEO에 특히 유리

## 6. SEO / AEO / GEO 적용 규칙 (자동화에서 추가할 것)

기존 글에 이미 있는 강점은 **유지**, 부족한 부분은 **보강**한다.

### 6.1 이미 잘하고 있는 것 (그대로 유지)

| 요소 | 효과 |
|---|---|
| ● 정보블록 (위치/시간/주차/가격) | AEO 직답 + GEO 인용 가능한 구조화 사실 |
| 질문형 소제목 (`맛은?`, `어떤 곳일까?`) | AEO — 검색 질의문과 소제목이 일치 |
| 장단점 명시 섹션 | GEO — LLM이 균형 잡힌 출처로 선호 |
| 단위 환산 가격 | GEO — 수치 비교에 인용됨 |
| 실측 정보(도보 n분, m 거리) | 신뢰도 신호 |

### 6.2 보강할 것

1. **첫 문단 직답화** — 도입 3~5줄 안에 결론 한 줄을 넣는다.
   예: "결론부터 말하면 조용히 작업하기에는 좋고, 주차는 어렵습니다."
   → AEO/GEO에서 첫 문단이 추출될 확률이 높다.
2. **소제목을 완전한 질문형으로** — `주차` → `망원동 카페 물루 주차 가능한가요?`
   단, 하우스 톤 유지를 위해 전부 바꾸지 말고 **섹션의 절반 정도**만 질문형으로.
3. **엔티티 명확화** — 상호명 정식 표기를 본문 첫 등장 시 1회 명시
   (예: "카페 물루(Cafe Mullu)"). LLM의 엔티티 연결에 유리.
4. **날짜 명시** — "2026년 8월 기준 가격입니다" 한 줄. 정보 신선도 신호.
5. **마무리 요약 3줄** — 클로징 총평 앞에 `· 좋았던 점 / · 아쉬운 점 / · 추천 대상`
   불릿 3줄을 넣으면 GEO 인용률이 크게 오른다. 하우스 톤과도 충돌하지 않음.

> ⚠️ **하지 말 것**: 키워드 반복 삽입(스터핑), 이모지 추가, 정보블록을 표(table)로 바꾸기.
> 네이버 C-Rank/DIA+는 체류시간과 실제 경험 신호를 보므로, 사진·개인 경험 문장이 우선이다.

## 8. 확정 사항 / 남은 것

**확정**
- 서브카테고리 3종(장소형·물건형·혼합형)으로 분기 — §0
- 작성자별 톤 구분 없음. 통합 하우스 보이스 하나 — §2.2
- 발행 단계에서 "누구로 발행할까요?"(징키/링키) 선택 → 서명 라인에 치환 — §2.6

**남은 것**
- 클로징 **배너 이미지**는 고정 자산이므로 웹앱에 업로드해두고 자동 삽입 가능
- 네이버 블로그 **카테고리 매핑**: 이 블로그는 "외식 리뷰 / 차생활 / 식생활 소식 /
  간식 리뷰 / 산책, 여행기"를 쓰고 있다. 발행 시 어떤 네이버 카테고리에 넣을지
  서브카테고리에서 자동 추천할 수 있음 (장소형→외식 리뷰, 물건형→소재에 따라 분기)
