## v2 → v3 변경 내역

작성자가 실제 계량과 조리 노하우를 확정하면서 **조리 순서 자체가 바뀌었다.**

| 항목 | v2 (추정) | v3 (확정) |
|---|---|---|
| 오크라 | 8개 | **10개** |
| 양파 | 1/2개 | **1/4개 (주먹만한 것)** |
| 양념 | 된장 또는 쌈장 1T | **된장 1T + 쌈장 1T** |
| 데치는 법 | 끓는 물에 넣기 | **커피포트에 끓인 물을 붓기** |
| 데치는 시간 | 30초~1분 | **2분 이내** |
| 데칠 때 소금 | 잔털 제거용 | **데치는 물에 넣어 색감 살리기** |
| 꼭지 자르는 시점 | **데치기 전** | **데친 후** (영양분 유출 방지) |
| 익음 판정 | 없음 | **레드 오크라 색이 연해지면 완료** |
| 팁 개수 | 4개 | 5개 (전부 작성자 고유) |

### 이번 판이 앞선 두 판과 다른 점

v1·v2의 팁은 내가 일반 지식으로 채운 것이었다. v3의 팁은 **다섯 개 전부 작성자가 직접
겪어서 알아낸 것**이다. 특히 아래 둘은 검색으로 나오지 않는다.

- **커피포트 물로 데치기** — 냄비에 계속 가열하면 물러진다는 문제의 해법.
  물 온도가 서서히 내려가서 과조리를 막는다. 이게 `style-profile-recipe.md` §8-3이 말하는
  "실패 지점"에 정확히 대응한다.
- **레드 오크라를 익음 판정 지표로 쓰기** — 초록만 데치면 색으로 구분이 안 되는데,
  레드를 하나 섞으면 색이 연해지는 것으로 건질 때를 안다.
  Q2 섹션과 팁 2번이 이 하나의 발견에서 나왔다.

두 번째 항목은 사진으로도 증명된다 (사진 1 = 생것, 사진 5 = 데친 것).

## v6 — 제목·소제목 근거 재정립

작성자 지적: 기존 9편에서 제목 공식을 뽑는 것은 근거가 약하다. 성과 데이터가 없는 표본이다.
타당하다. `data/raw/naver_official/` 의 네이버 공식 가이드 2편을 1차 근거로 다시 잡았다.

### 공식 문서가 제목에 대해 말하는 것

공식 가이드에는 **제목 공식이 없다.** 대신 배제 기준이 있다.

> - "반복적인 키워드 나열, 낚시성 문서 … 는 걸러질 가능성이 높습니다"
> - "오직 노출만을 목적으로 맥락과 관계 없는 키워드를 억지로 끼워 넣지 마세요"
> - FAQ 6: "과거의 **기계적인 최적화 방식에서 벗어나** 사용자 중심으로 변화하고 있기 때문에"

v1~v5의 제목은 이 배제 기준에 걸린다.

```
오크라무침 오크라손질법 데치는법까지, 커피포트 활용 맛보장 꿀팁
```

- `오크라` 2회 반복 + 키워드 3개 나열 → 반복적인 키워드 나열
- `맛보장`, `꿀팁` → 정보 없는 신호어. 구식 SEO 문법

`style-profile-recipe.md` §7의 신호어 사전이 그 구식 문법을 그대로 담고 있었고,
9편 표본이 우연히 그 문법을 쓰고 있었다는 이유로 재생산됐다. **§7을 폐기하고 다시 쓴다.**

### 새 제목 원칙 (공식 문서에서 도출)

1. 핵심 검색어 하나를 앞에. **중복 금지**
2. 이 글에만 있는 것을 뒤에 ("창작자만이 알고 있는 팁")
3. 제목이 약속한 것을 본문이 지킬 것 (낚시 배제)

```
확정: 오크라무침 만드는법, 커피포트 물로 데치면 안 물러져요
대안: 오크라 데치는 시간 2분, 붉은 오크라 색으로 확인하세요
대안: 오크라무침 레시피, 데치면 비타민C가 줄어듭니다
```

### 소제목 2개 추가 — 인용 단위 확보

AI 브리핑은 본문을 조각내 인용한다. v5까지 **조리 단계 구간에 소제목이 없었다.**
공식 체크가이드가 가장 강조하는 "절차 및 구체적 해결 과정" 구간인데 잘라 갈 손잡이가 없었다.

실제 검색 질의 형태로 두 개를 넣었다. 둘 다 바로 뒤에 이 글만의 답이 온다.

| 소제목 | 위치 | 바로 뒤에 오는 고유 정보 |
|---|---|---|
| `오크라 데치는 시간, 몇 분이 맞을까요?` | 단계 2 앞 | 커피포트 물 / 2분 / 레드 오크라로 판정 |
| `꼭지는 언제 자르나요?` | 단계 3 앞 | 데친 뒤에 자른다 + 이유 |

제목보다 이쪽이 인용에 더 크게 작용한다.

### 아직 검증하지 못한 것

- 네이버는 **CTR을 공개하지 않는다.** 어떤 제목이 실제로 더 눌리는지는 발행 후
  블로그 통계(유입 검색어·조회수)로만 알 수 있다.
- 검색량 데이터를 조회하지 않았다. `오크라 데치는 시간` 같은 표현이 실제 질의인지는
  네이버 자동완성으로 확인해야 한다.
- **→ 웹앱에 제목 성과 추적을 넣어야 한다.** 발행 시 제목 후보와 선택안을 기록하고,
  2주 뒤 유입 검색어를 대조해 원칙을 갱신하는 루프. 이게 없으면 계속 추측이다.

## Q3(영양 블록) — 확정 완료

`*.nics.go.kr` 허용 후 1차 출처에서 직접 조회했다. 농식품올바로가
`koreanfood.rda.go.kr` → `www.nics.go.kr/food` 로 이전해 있어 두 도메인이 모두 필요했다.

**조회 결과 — v1~v3에 쓰려던 수치가 틀렸다.**

| | v1~v3 (검색 요약본) | v4 (국가표준식품성분표) |
|---|---|---|
| 에너지 | 33kcal | **26kcal** |
| 총 식이섬유 | 3.2g | **5g** |

33kcal / 3.2g 은 미국 USDA 값이었다. 한국 성분표 값과 다르다.

### 이 데이터가 글에서 하는 일

**생것과 데친것이 따로 등재돼 있다는 점**이 이 레시피와 정확히 맞물린다.
데치는 레시피이므로 "데치면 뭐가 달라지나"에 성분표로 답할 수 있다.

- 데치면 수분이 빠져 100g 기준 열량·식이섬유가 소폭 상승
- **비타민 C는 11 → 7 mg 으로 감소** (물에 녹아나감) → 짧게 데치라는 조리 조언과 직결
- 미끈한 점액의 정체인 수용성 식이섬유는 1.4 → 1.6 g 으로 줄지 않음

일반적인 "오크라 효능" 글에는 없는 각도다. 검증 가능한 1차 출처 + 이 레시피에만 맞는 해석이라
GEO 관점에서 인용 단위로 쓸 만하다.

## 프로파일에 반영할 것

이번 한 편에서 나온, `docs/style-profile-recipe.md` 에 되먹임할 항목.

1. **팁 개수 상한을 4 → 5로** 상향. 작성자 고유 정보가 많을 때 규격이 오히려 방해가 된다.
2. **`조리 도구·화력` 항목 신설.** "커피포트에 끓인 물" 같은 정보는 재료준비 블록에
   들어갈 자리가 없었다. `데칠때` 그룹에 도구를 함께 적는 것으로 처리했으나,
   별도 필드로 두는 편이 낫다.
3. **1차 출처 조회를 생성 파이프라인에 넣는다.** 이번에 검색 요약본 수치(33kcal/3.2g)가
   실제 한국 성분표 값(26kcal/5g)과 달랐다. 식재료 영양 정보는 농식품올바로
   `www.nics.go.kr/food` 의 `fdnmList.json` + `detailOne` 두 엔드포인트로 자동 조회가 된다.
   식품코드만 잡으면 생것/데친것/볶은것을 함께 가져올 수 있어, 조리법에 맞는 비교가 가능하다.
4. **손질 순서의 근거를 묻는 질문 추가.** "꼭지를 언제 자르나요?" 같은 질문은
   웹앱이 먼저 물어야 한다. 이번에는 내가 틀린 순서로 두 판을 썼다.
5. **사진 판독은 초안보다 먼저 해야 한다.** v1~v4에서 "꼭지 돌려깎기" 손질을 네 판 연속
   본문에 썼는데, 작성자는 그런 손질을 한 적이 없다. 내가 먼저 써둔 문장이 사진 판독을
   끌고 갔다. 웹앱에서는 사진을 먼저 읽고 무엇이 찍혔는지 **작성자에게 확인받은 뒤**
   본문을 쓰는 순서로 고정한다. 사진 설명은 추측이 아니라 확인된 사실만 넣는다.
6. **§7 제목 공식을 폐기하고 위 3원칙으로 교체한다.** 신호어 사전
   (`맛보장` `꿀팁까지` `황금레시피` 등)은 네이버가 배제하는 키워드 나열에 해당한다.
   과거 글 9편은 **하우스 보이스(말투·이모지·분량)의 근거일 뿐, 성과의 근거가 아니다.**
   두 용도를 문서에서 분리한다.
7. **절차 구간에 질의형 소제목을 최소 2개 강제한다.** 조리·손질 단계는 AI 브리핑이
   가장 많이 인용하는 구간인데 소제목이 없으면 잘라 갈 단위가 안 된다.
8. **익음·완성 판정 지표를 필수 질문으로.** "다 됐는지 어떻게 아나요?"는
   레시피 검색에서 가장 많이 나오는 질의인데 v1·v2에 아예 없었다.
