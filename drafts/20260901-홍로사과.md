**`수확시기`가 세 갈래 표현으로 반복 등장**해 제목 앞자리에 놓았다.

다루지 않은 질의와 이유:

| 질의 | 이유 |
|---|---|
| 홍로 사과 세척법 | 1차 출처에 없다. 일반 사과 세척법을 홍로 것처럼 쓰지 않는다 |
| 사과 홍로 가격 | 시세는 출처 확보가 어렵고 금방 낡는다 |
| 홍로 아리수 비교 | 아리수 자료 미확보 |
| 홍옥 비교 | 성분표에 홍옥은 있으나 홍로가 없어 반쪽 비교가 된다 |

## 3. ⚠️ 사전 지식과 원문이 달랐던 항목 — 5건

작성자가 다른 대화에서 받았던 정리표와 원문을 대조한 결과다.
**5건 중 3건이 수치 불일치였다.**

| 항목 | 사전 지식 | **원문** |
|---|---|---|
| 과중 | 250~350g | **300g** |
| 저장성 | 상온 2주 / 냉장 1~2개월 | **상온 30일** |
| 산도 | 0.3% | **0.25~0.31%** |
| 교배 모본 표기 | 스퍼얼리블레이즈 × 스퍼골든딜리셔스 | **스퍼어리브레이즈 × 스퍼골든데리셔스** |
| 수확기 | 8월 하순~9월 중순 | **9월 상·중순 (8월 하순부터 수확 가능)** |

원문에 **없어서 쓰지 않은 것**:

- 재배면적 2위 — 연도별로 바뀌는 통계다. 기준 연도 없이 쓰면 오정보가 된다
- 고두병 — 원문 병해 목록은 점무늬낙엽병·역병·줄기겹무늬썩음병이다
- 밀 부위의 저장 중 갈변 — 원문은 "저장에 불리"까지만 적혀 있다
- 고르기 요령(무게감·꼭지 상태) — 원문에 없다
- 주산지 목록 — 원문에 없다

원문에 **있어서 새로 넣은 것**:

- **국내에서 육성된 최초의 사과 품종** ← 이 글의 후킹이 됐다
- 조기결실성·풍산성·수확 전 낙과 없음 → "왜 추석 사과가 됐나" 섹션의 근거
- 해발이 낮고 온도가 높은 지역에서도 착색 양호
- 농가 관리(적화·적과, 잎따기, 약제 시기) → 다른 블로그에 없는 각도

## 5.5 v4 — 독자 장면 기준으로 재배열

작성자 지적: 시장에서 처음 본 사람이 AI에 뭘 물을지, 어떤 순서로 답할지를 기준으로 쓰자.

**v1~v3은 자동완성 순위와 자료 목차를 따라갔다.** 그 결과 시장에서 홍로를 처음 본
사람이 가장 먼저 묻는 "무슨 맛이야"가 세 번째에 있었다.

| | v3 순서 | v4 순서 |
|---|---|---|
| 1 | 수확시기 (핵심 답) | **맛** — 살지 말지 |
| 2 | 어떤 사과인가 (유래) | **제철** — 사도 되나 |
| 3 | 맛 | **보관·구매량** — 몇 kg |
| 4 | 색 | **고르는 법** — 고르는 중 |
| 5 | 보관 | 밀증상 |
| 6 | 밀증상 | 어떤 사과인가 (유래) |
| 7 | 추석 사과가 된 이유 | 추석 사과가 된 이유 |
| 8 | 농가 관리 | 농가 관리 |

**핵심 답 요약도 바뀌었다.** `수확시기는?` → **`사도 될까요?`**
독자가 실제로 내리려는 결정에 답한다.

신설: `어떤 걸 고르면 좋을까요?` — 원문의 품종 특성(농홍색·줄무늬 없음·그늘 착색 불량·
대과 밀증상)을 소비자 관점으로 뒤집어 구성했다. **원문에 고르기 요령이 적혀 있는 것은
아니므로**, 본문에서 "자료에는 ~라고 적혀 있어요 → 그래서 이렇게 보시면 돼요" 형태로
사실과 해석을 분리해 썼다.

제목도 바꿨다.

```
v3  홍로사과 수확시기, 국내에서 처음 만든 사과 품종이에요
    → '사과' 중복. 앞(실용)과 뒤(역사)가 다른 축

v4  홍로사과 맛은 어떤가요? 단맛 위주에 신맛이 거의 없어요
    → 질문 + 답. 앞자리 '홍로사과 맛'은 자동완성 존재. '사과' 1회
```

질문형 제목은 정보성 과거 글에도 있던 형태(`샐러리잎 맛있게 먹는법?`,
`수박, 다이어트에 효과 있을까?`)이고, 폐기한 낚시 어구와 달리 **제목이 곧 질의**라
AEO에도 유리하다.

## 5.6 v5 — 보관 방법 섹션 신설

작성자 지적: `얼마나 두고 먹어?` 다음에 **보관 방법**이 있어야 한다.

품종 요약자료에는 저장 기간(상온 30일)만 있고 방법이 없었다.
일반 상식으로 쓰면 규칙 위반이라 1차 출처를 찾았다.

| 시도 | 결과 |
|---|---|
| 농사로 영농기술 자료 | 접속 불안정 |
| rda.go.kr 보도자료 게시판 검색 (`사과`, `저장`) | 해당 자료를 찾지 못함 |
| **웹 검색 → 기사 → 원 발표 확인 → rda.go.kr 원문** | **확보** ← 작성자 제안 경로 |

확보한 1차 출처:

> 농촌진흥청 국립원예특작과학원 보도자료
> 「'더 오래 신선하게' 똑똑한 과일, 채소 보관법」 2023-09-27
> 공공누리 제1유형(출처표시)

원문에서 가져온 내용:

- 사과 최적 보관 조건 **0℃, 상대습도 90~95%**
- 가정용 냉장고 냉장실 4~5℃ / 김치냉장고 0~15℃ → **사과는 김치냉장고**
- 사과는 에틸렌 생성량이 많아 **따로 보관**
- 에틸렌에 민감한 채소: **브로콜리, 상추, 오이, 수박, 당근** — 변색·반점

원문에 없어서 쓰지 않은 것: 비닐봉지 밀봉.
(잎채소에만 해당하는 서술이고, 사과에 대한 언급은 없다.
사전 지식 표에는 "냉장에 비닐봉지로 밀봉"이 있었으나 근거를 찾지 못했다.)

### 되먹임 — 언론 경유 경로를 규격에 넣었다

기사 자체는 2차라 인용하지 않지만, **기사가 인용한 기관 발표를 찾아가는
길잡이로는 유효하다.** 기관 사이트의 자체 검색이 부실할 때 오히려 빠르다.

## 5.7 v6 — 규격 라벨 유출과 요약-본문 중복

작성자 지적 두 건. 둘 다 규격을 만든 내가 규격을 잘못 적용한 경우다.

### 1. `핵심 답` 라벨이 본문에 새어 나갔다

`style-profile-info.md` 에 요약 블록 서식을 이렇게 적어두었다.

```
핵심 답
{제목의 질문을 한 번 더}
{결론 1~2문장}
```

여기서 `핵심 답` 은 **"이 자리에 이런 블록이 온다"는 표시**이지 독자가 읽을 문구가 아니다.
과거 27편에도 그런 라벨은 없다. 그런데 서식을 그대로 본문에 옮겼다.

레시피의 `재료준비` 는 과거 글 9/9에 실제로 있는 라벨이라 유지가 맞지만,
`핵심 답` 은 규격을 설명하려고 내가 붙인 이름이다.

> **되먹임** — `docs/document-structure-spec.md` 에
> "규격 문서의 라벨을 본문에 넣지 않는다" 절을 신설했다.
> **과거 글에 실제로 등장하는 라벨만 본문에 쓴다.**

### 2. 요약과 본문 첫 섹션의 문장이 겹쳤다

```
v5 요약   단맛 위주에 신맛이 거의 없어요
v5 본문   단맛 위주이고 신맛이 적어요
```

원인은 구조에 있다. **요약 블록이 답을 나열하고, 바로 다음 섹션이 같은 답을 반복한다.**
요약과 첫 소제목이 같은 층위에 놓이기 때문이다.

v6에서 층위를 나눴다.

| | 성격 | v6 |
|---|---|---|
| 요약 | **판단** | "단맛을 좋아하시면 사세요. 오래 두고 먹는 사과는 아닙니다" |
| 본문 | **사실** | "당도 14~15%, 산도 0.25~0.31%. 육질은 단단하고 과즙은 적어요" |

독자가 요약에서 얻는 것은 **결정**, 본문에서 얻는 것은 **근거**다.
층위가 다르면 중복이 아니다. 같은 문장을 두 번 쓰면 중복이다.

이 원칙도 `style-profile-info.md` 요약 블록 절에 넣었다.

## 5.8 v7 — 제목 작성 기준 12항목 적용

작성자가 「네이버 블로그 제목 작성 기준 — CTR × GEO 최적화」를 제공했다.
`docs/title-heading-spec.md` §1을 이 기준으로 다시 썼다.

기존 규격에 **없던 7개 항목**을 추가했다.

| 추가 항목 | 내용 |
|---|---|
| 제목-본문 연관도 | 제목 키워드가 본문에 1회 이상 재등장 |
| 조사·부사어구 최소화 | `~에 대해서`, `~에 관한` 삭제 |
| CTR 공식 6가지 중 2개 이상 | 숫자·질문형·문제해결·비교·최신성·이득 |
| 구체적 조건(Modifier) | 지역·대상·시점·규모 |
| 하나의 글 = 하나의 entity | 제목이 하나의 사용자 의도에 정렬 |
| 제목 핵심어 ↔ 소제목 연결 | 구조 일치 |
| 유사 제목 반복 발행 지양 | 발행 이력 검사 필요 |

길이 규격도 **25~40자 → 20~30자**로 좁혔다.

### 두 편 점검 결과

| 글 | 길이 | CTR 공식 | 판정 |
|---|---|---|---|
| 오크라 (발행완료) | 30자 | 2가지 (숫자·문제해결) | **통과** |
| 홍로 v6 | 31자 ✕ | 1가지 (질문형) ✕ | **미달** |

오크라는 손댈 것이 없다. 홍로 제목을 바꿨다.

```
v6  홍로사과 맛은 어떤가요? 단맛 위주에 신맛이 거의 없어요   31자 / CTR 1가지
v7  홍로사과 맛은? 9월 제철, 신맛이 거의 없어요              24자 / CTR 3가지
```

- `어떤가요?` → `맛은?` 으로 압축 (조사·부사어구 최소화)
- `9월 제철` 추가로 **숫자 + 최신성 + 구체적 조건**을 동시에 확보
- `단맛 위주에 신맛이 거의 없어요` 에서 `사과예요` 를 뺀 것은
  `홍로사과` 와 형태소가 겹치기 때문

### ⚠️ 자료의 근거 수준

이 문서의 출처는 개인 블로그·티스토리이며 **네이버 공식 문서가 아니다.**
규격에 「공식」/「통설」로 근거를 표시해 구분했다.

다만 내용이 공식 가이드와 충돌하지 않고, 특히 자료 스스로
"낚시성 과장은 초기 클릭은 늘려도 체류시간·재방문율을 깎아 D.I.A+에 불리"라고
경고하는 점이 내가 폐기한 후킹 어구 판단과 일치한다.

CTR 공식 6번 `이득 명시형` 만 주의가 필요하다. `놓치면 손해` 계열은
이미 폐기한 어구이므로, **이득이 구체적으로 무엇인지 제목에 드러날 때만** 쓰도록
단서를 달았다.

## 5.9 v8 — 제목 생성 절차 적용

작성자가 제공한 「네이버 블로그 제목 생성 프롬프트」를 검토·채택하고
`docs/prompt-title-heading.md` 로 만든 뒤, 그 절차대로 후보 8개를 만들어 검증했다.

| # | 제목 | 자수 | CTR 공식 | GEO형 | 판정 |
|---|---|---|---|---|---|
| **1** | **홍로사과 처음 보셨나요? 9월 제철 단맛 품종이에요** | **28** | **B2+B1+B5** | **O** | **추천** |

| 3 | 홍로사과 왜 추석에만 보일까요? 수확기가 답이에요 | 27 | B2+B3 | O | 통과 |
| 4 | 홍로사과 신맛 없는 이유? 산도가 0.3% 미만이에요 | 29 | B2+B1 | O | 통과 |

### 추천 근거

`홍로사과 처음 보셨나요? 9월 제철 단맛 품종이에요`

- **후킹 어구 `~보셨나요?` 를 썼다.** 궁금증 간극이 살아 있고,
  §0 조건(서론 100~150자 직답)을 서론 첫 문단이 충족한다.
- 독자 장면(시장에서 처음 봄)과 제목이 직접 대응한다.
- CTR 3가지 조합 — 질문형 + 숫자(9월) + 최신성(제철)
- 형태소 `사과` 1회. 특수문자 `?` 1개.
- GEO C2 구체적 조건: `9월 제철`

3번(`왜 추석에만 보일까요?`)이 후킹은 더 강하지만, 본문의 중심 각도가 '맛'이고
추석 이야기는 일곱 번째 섹션이라 **제목-본문 구조 일치(C7)에 어긋난다.**

### 서론 재조정

제목이 `단맛 품종`을 약속하므로 서론이 그것을 받아야 한다.
그런데 서론에 맛을 넣으니 **바로 다음 판단 블록과 다시 겹쳤다.**

```
서론      홍로는 9월이 제철인 국산 사과 품종이에요        ← 제목의 '9월 제철' 직답
판단 블록  단맛을 좋아하시면 사세요.
          신맛이 거의 없고 단맛 위주라 호불호가 갈려요    ← 제목의 '단맛' 직답
```

둘을 나눠 배치해 중복을 없앴다. 제목 직후 67자 안에서 두 약속이 모두 지켜진다.

## 5.10 v10 — 제목을 살리고 본문을 재배열

작성자 반박: 추석 시즌이라 `왜 추석마다` 후킹이 강하고,
본문에서 추석과 수확기를 연결해 풀면 어색하지 않다.

**내가 이 후보를 탈락시킨 두 근거가 모두 잘못이었다.**

| 내 근거 | 실제 |
|---|---|
| `홍로 추석` 이 자동완성에 없다 | **뒷부분은 CTR 담당이지 검색 매칭 담당이 아니다.** 검색은 앞자리 `홍로사과` 가 한다 |
| 추석 내용이 본문 아홉 번째 섹션이다 | **본문을 고치면 된다.** 제목을 본문에 맞출 생각만 하고 반대 방향을 보지 않았다 |

### 확인한 사실

2026년 추석은 **9월 25일(금)**이다. 홍로 수확기(8월 하순~9월 상·중순) 직후라
"수확하자마자 매대에 오른다"는 서술이 정확하다.

### 제목

```
✕  홍로사과 왜 추석에만 보일까요?     '~에만'은 사실이 아니다. 8월 하순부터 나온다
○  홍로사과 왜 추석마다 나올까요? 9월 수확기가 답이에요   28자
```

한 글자 고쳤다. 원칙 3(제목이 약속한 것을 본문이 지킬 것)에 걸리기 때문이다.

### 본문 재배열

기존 3번(`지금 사도 되는 철인가요?`)과 9번(`왜 추석 사과가 됐을까요?`)을
**하나로 합쳐 두 번째 섹션으로 올렸다.**

```
v8   판단 → 맛 → 제철 → 구매량 → 보관 → 고르기 → 밀 → 정체 → 추석이유 → 재배
v10  판단 → 추석·수확기 → 맛 → 구매량 → 보관 → 고르기 → 밀 → 정체 → 재배
```

섹션 10개 → 9개. 중복 서술이 사라져 본문은 2,048자로 유지됐다.

서론도 조정했다. 제목 직답을 넣었더니 새 섹션과 또 겹쳐서,
**서론은 한 줄 직답만, 수치는 섹션에** 두었다.

```
서론    홍로 수확기가 추석과 겹치기 때문이에요        ← 직답
섹션    8월 하순부터 딸 수 있고 본격 수확기는 9월 상·중순.
        2026년 추석은 9월 25일이니 수확하자마자 매대에 오르는 셈  ← 근거
```

### 되먹임

`title-heading-spec.md` §1.1c를 신설했다.

| | 담당 | 검증 |
|---|---|---|
| 제목 앞부분 | 검색 매칭 | 자동완성 조회 필수 |
| 제목 뒷부분 | 클릭 유도 | 자동완성 불필요. 본문 앞쪽 섹션과 대응하면 된다 |

점검 7b도 고쳤다. "뒷부분도 검색 근거가 있는가" → **"뒷부분이 본문 앞쪽 섹션과
대응하는가. 뒤쪽이면 본문을 재배열한다."**

## 5.11 v11 — 서명·훅을 제목 각도에 맞춤

작성자 지적: 제목에서 `처음 보셨나요` 를 탈락시켜 놓고 서명 라인은
`처음 본 사과 홍로_by징키` 로 그대로 두었다.

### 검색 이슈는 아니다

**서명 라인과 훅 소제목은 검색 대상이 아니다.** 검색되는 것은 제목뿐이므로
`처음 본` 이 검색어가 아니어도 그 자체로는 문제가 되지 않는다.

### 진짜 문제는 방향 불일치

제목이 두 번 바뀌는 동안 서명과 훅은 v4 상태로 남아 있었다.

```
제목    홍로사과 왜 추석마다 나올까요? 9월 수확기가 답이에요   v10
서명    처음 본 사과 홍로_by징키                            v4
훅      시장에서 만난 / 낯선 사과, 홍로                      v4
```

앞의 둘은 "시장에서 처음 봄" 장면 기준, 제목은 추석·수확기 각도다.
**글이 두 방향을 가리킨다.**

수정:

```
서명    추석 사과의 정체 홍로_by징키
훅      수확기가 추석과 겹치는 / 국산 사과 홍로
```

### 같은 실수를 두 번 했다

오크라 v7에서 정확히 이 문제를 겪고 되먹임까지 적었다.

> "본문 일부를 삭제·수정할 때, 그 내용을 전제로 쓴 서명 라인·훅 소제목·도입부를
> 함께 검사해야 한다."

**만들어 놓고 실행하지 않았다.** `document-structure-spec.md` 점검 목록에
항목으로 못박고 별도 절로 사례를 남겼다.

## 5.12 v12 — 섹션을 옮기며 깨진 연결 복구

작성자 지적: 판단 블록이 `아래는 그렇게 말씀드리는 근거예요` 로 끝나는데
바로 다음이 `홍로사과는 왜 추석마다 나올까요?` 다.

v10에서 추석 섹션을 두 번째로 올릴 때 **판단 블록의 마무리 문장을 확인하지 않았다.**
v8까지는 다음이 `맛` 이라 문장이 맞았다.

### 순서 재조정

가리키는 문장을 고치는 것보다 순서를 맞추는 쪽을 택했다.

```
v10  서론 → 판단 → 추석·수확기 → 맛 → 구매량 → 보관 → …
v12  서론 → 추석·수확기 → 판단 → 맛 → 구매량 → 보관 → …
```

이 순서가 독자 동선과도 맞는다.

| 순서 | 역할 |
|---|---|
| 서론 | 제목 질문에 한 줄 직답 |
| 추석·수확기 | 제목 질문의 상세 답 |
| **판단 블록** | 궁금증이 풀린 뒤 나오는 다음 질문 — "그래서 살까?" |
| 맛·구매량·보관·고르기 | 판단의 근거 |

판단 블록 마무리도 뒤 섹션을 정확히 가리키도록 고쳤다.

```
✕  아래는 그렇게 말씀드리는 근거예요. 농촌진흥청 품종 자료를 바탕으로 하나씩 정리했어요.
○  맛, 살 양, 보관법, 고르는 법을 농촌진흥청 자료를 바탕으로 아래에 하나씩 정리했어요.
```

### 되먹임

`document-structure-spec.md` 점검에 항목을 추가하고 사례 절을 신설했다.

```
[ ] 섹션 순서를 바꿨다면 앞뒤를 잇는 문장을 함께 확인했다
```

**무언가를 옮기면 그것을 참조하던 것을 함께 봐야 한다.**
v11(제목 바꾸고 서명·훅 안 봄)과 같은 유형의 실수다.

## 5.13 v13 — 출처의 전문용어를 풀어씀

작성자 지적: `조기결실성이고 풍산성이에요` 가 너무 어렵다.

그 한 줄만의 문제가 아니었다. 글 전체를 훑으니 **원문 용어가 14개** 그대로 넘어와 있었다.

```
조기결실성 · 풍산성 · 낙과 · 착색 · 농홍색 · 식미 · 육질 · 저장성
과피색 · 대과 · 병해 · 해거리 · 점무늬낙엽병 · 줄기겹무늬썩음병
```

### 순서가 거꾸로였다

용어를 먼저 쓰고 뒤에 설명을 붙였다. **독자는 첫 줄에서 막힌다.**

```
✕  1) 조기결실성이고 풍산성이에요
      나무가 일찍부터 열매를 맺고 수확량이 많다는 뜻이에요

○  1) 한 나무에서 많이 열려요
      어린 나무일 때부터 열매가 달리고 수확량도 많은 품종이에요
```

### 주요 수정

| 원문 용어 | 고친 표현 |
|---|---|
| 조기결실성·풍산성 | 한 나무에서 많이 열려요 |
| 수확 전 낙과가 거의 없어요 | 익는 동안 잘 안 떨어져요 |
| 착색이 양호하다 | 색이 잘 든다 |
| 과피색이 농홍색 | 껍질이 진한 붉은색 |
| 육질은 단단하고 식미는 양호 | 씹는 느낌은 단단하고 맛은 좋은 편 |
| 저장성이 상온 30일 | 상온에서 30일 정도 둘 수 있다 |
| 대과는 밀증상 발생이 많다 | 큰 열매일수록 밀이 많이 생긴다 |
| 점무늬낙엽병·줄기겹무늬썩음병 | 잎에 점이 생겨 떨어지는 병, 줄기가 썩는 병 |
| 이듬해 수확이 줄어드는 해거리 | 이듬해에 열매가 확 줄어요. 이걸 해거리라고 부릅니다 |

`밀증상` 은 남겼다. **태그에 넣은 검색어**이기 때문이다.
`해거리` 도 남겼으나 설명을 앞으로 보냈다.

부수적으로 v12 재배열 때 생긴 **구분선 중복 1건**도 제거했다.

### 되먹임

`document-structure-spec.md` 에 절과 점검 항목을 추가했다.

```
[ ] 출처의 전문용어를 그대로 옮기지 않았다
```

**정보성에서 특히 위험하다.** 경험형은 작성자가 자기 말로 쓰니 이 문제가 잘 안 생기는데,
정보성은 출처를 그대로 옮기기 쉬워 전문용어가 그대로 넘어온다.
오크라 글에는 이런 문제가 없었고 홍로 글에서 14개가 나온 이유다.
